v25 — v10 아키텍처 + 전처리 팀 새 데이터: 62.58%로 대폭 하락

[이 버전을 시작한 계기]

v23(67.73%)·v24(64.37%)로 multi-scale conv가 역효과임이 확인됐다.
"아키텍처 탐색" 단계의 결론: v8/v10의 단순 Conv1d(k=3)×2가 이 데이터에 가장 적합.

동시에 전처리 팀에서 새 데이터(DB2_output.zip)가 도착했다.
전략: "전처리가 어떻게 됐는지 분석하고, 검증된 최고 모델(v10)로 기준선 확보 후 발전."
→ v25 = v10 아키텍처 그대로, 새 데이터만 교체. 기준선(baseline) 확보 목적.


[방법: code/train_cnn_v25.py]

아키텍처: v10과 100% 동일.
  Conv1d(24→64, k=3) + BN + ReLU
  Conv1d(64→128, k=3) + BN + ReLU
  BiLSTM(128, 2L, bidir, dropout=0.3)
  Attention weighted sum → (B, 256)
  SubjectEmbedding(40, 32) concat
  Dropout(0.4) + Linear(288, 50)

데이터: 전처리전달/ (팀 전처리 완료, per-subject 정규화 적용된 상태로 제공)
  X_train.npy / y_train.npy / s_train.npy
  X_val.npy   / y_val.npy   / s_val.npy
  X_test.npy  / y_test.npy  / s_test.npy
  norm_mean.npy / norm_std.npy (피험자별 정규화 통계)

정규화: 새 데이터는 전처리 팀이 per-subject 정규화를 완료했다고 판단.
  → EMGDataset에서 추가 정규화 미적용.
  → 데이터를 그대로 모델에 입력.

하이퍼파라미터: v10과 동일 (AdamW 1e-3, CosineAnnealingLR, 50ep, patience=8, batch=256)

[기대와 실제가 어떻게 달랐는가]

기대: 전처리 팀이 더 정교한 방법을 사용했으니 v10(69.10%) 이상을 기대.
     최소한 비슷한 수준(68~70%) 예상.

학습 곡선도 v10보다 불안정(ep16 급락).


[원인 분석: 진단 결과]

데이터 이상 여부 점검:
  1. 채널별 통계 (ch0~23 std) — 우리 데이터 vs 팀 데이터:
     거의 동일. ch0: 0.9680 (팀) vs 0.9846 (우리). 통계적 차이 없음.

  2. 분할 크기:
     train: 팀=447,047  우리=447,610  (diff=-563, 무시 가능)
     val  : 팀=108,303  우리=108,323  (diff=-20)
     test : 팀=108,171  우리=108,171  (동일)
     → 거의 동일. 분할 방식은 같음.

  3. 데이터 값 범위 (2,000 샘플 비교):
     train: mean=-0.0294  std=0.9307  min=-136.92  max=85.63
     val  : mean=-0.0203  std=0.9801  min=-35.10   max=45.64
     test : mean=-0.0262  std=0.9605  min=-41.36   max=43.09

     → train에만 극단값 존재 (|max|=136.92),
       val/test는 ±43~45 범위에 제한됨.
     → train-val/test 간 분포 불일치 가능성.

가설 (v26에서 검증):
  전처리 팀이 per-subject 정규화를 적용했으나, 이것이 오히려 성능 저하 원인일 수 있음.
  이유:
    a) Per-subject 정규화는 피험자 간 스케일 차이를 제거함.
       v10은 global 정규화로 hard 피험자의 신호 크기도 보존 → 모델이 암묵적으로 활용.
    b) Per-subject 정규화 후 train set에 이상치(아티팩트) 세션이 포함됐을 때,
       그 세션의 데이터가 val/test 분포와 크게 달라질 수 있음.

  → v26: 팀 데이터에 우리 방식(global norm, X_train 전체 mean/std) 재적용.
    v26 ≈ v10 → per-subject 정규화가 문제
    v26 << v10 → 데이터 내용 자체가 다름 (윈도우 위치, 라벨, 피험자 배정 등)


[v25 실험이 가르쳐 준 것]

- 전처리 팀 결과물을 "당연히 더 좋을 것"이라 가정하고 바로 쓰면 안 된다.
- Per-subject 정규화가 pooled model에서는 오히려 불리할 수 있다.
  (피험자 간 스케일 정보 = 묵시적 피험자 구별 단서를 제거함)
- 새 데이터 도입 시 분포 점검(train/val/test 값 범위, 극단값) 필수.
- v25의 학습 곡선 불안정성(ep16 급락)은 데이터 품질 문제의 시그널.


[향후 개선 후보]

1. (즉시, v26) 팀 데이터 + 우리 방식 global 정규화 재적용.
   → per-subject 정규화 영향 격리.

2. (v26 결과 따라) 정규화 방식 결정 후, v10 대비 개선점 탐색.
   - Hard subject oversampling (2~3×)
   - 더 많은 에포크 (100ep)
   - 두 데이터셋 합병

3. (장기) 전처리 팀과 구체적 전처리 파이프라인 문서 공유 요청.
   어떤 필터링, 어떤 정규화 통계 계산 기준인지 확인 필요.
