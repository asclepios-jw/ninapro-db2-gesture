================================================================
v20 — DANN lambda 축소(1.0→0.1): gap 역전 구조적 문제로 확인
================================================================

[이 버전을 시작한 계기]

v19(lambda=1.0)에서 hard 피험자 68.33%(역대 최고)를 기록했지만 easy 피험자가
61.42%로 폭락해 gap이 -6.90p로 역전됐다. 원인 가설: LAMBDA_DOMAIN=1.0이
12%/88% 불균형 상황에서 너무 강한 적대 신호를 만들어 feature가 hard-like로
과도하게 밀린 것. 이를 검증하기 위해 lambda를 1.0→0.1로 10배 축소.


[방법: code/train_cnn_v20.py]

train_cnn_v19.py에서 LAMBDA_DOMAIN만 0.1로 변경. 모델 아키텍처/학습 레시피
전부 동일(models_v19.py 재사용). 변경된 파라미터:

  LAMBDA_DOMAIN: 1.0 → 0.1


[재현 정보]

  python /mnt/data/medical_project/ninapro_db2_project/code/train_cnn_v20.py
  # CKPT: results/v20/best_model_v20.pth
  # 결과: results/v20/result_v20.json

[결과]

                    v8(단일)   v19(λ=1.0)   v20(λ=0.1)   변화
  전체 acc           68.69%      62.27%       63.00%       +0.73p
  전체 macro-F1      56.92%      44.64%       46.24%       +1.60p
  어려운 5명 acc      57.52%      68.33%       69.01%       +0.68p
  나머지 35명 acc     70.29%      61.42%       62.16%       +0.74p
  격차(easy-hard)    +12.77p     -6.90p       -6.85p       +0.05p

  dom_loss 수렴값: v19 ≈ 0.35  →  v20 ≈ 0.22
  (lambda가 10배 작아지자 domain classifier가 GRL에 덜 방해받아 loss가 낮아짐)


[기대와 실제가 어떻게 달랐는가]

기대: lambda를 1/10로 줄이면 GRL의 적대 신호가 약해져서 easy 피험자 손실이
완화되고 gap이 어느 정도 복원될 것.

실제: lambda를 10배 줄였는데 gap이 -6.90p → -6.85p로 0.05p밖에 변하지
않았다. dom_loss는 0.35→0.22로 크게 줄었음에도 gap은 거의 그대로였다.

이는 lambda 강도가 gap 역전의 원인이 아님을 보여준다. 즉 v19의 gap 역전은
"GRL 신호가 너무 강해서"가 아니라 구조적 원인에서 온 것이었다.


[원인 분석: gap 역전의 구조적 원인 확인]

도메인 라벨 불균형(hard 12.42% / easy 87.58%)이 핵심이다:

1. Domain classifier는 "항상 easy 예측" 시 87.58% 정확도를 얻는다. 따라서
   자연스럽게 easy 편향 분류기로 수렴한다.

2. GRL은 feature extractor에게 "domain classifier를 헷갈리게 만들라"는
   gradient를 전달한다. "easy처럼 보이지 않게" 만드는 것이 가장 쉬운 방법.

3. 결과적으로 feature가 hard-like로 이동한다 — lambda=1.0이든 0.1이든
   방향은 동일하다. lambda는 이동 속도만 조절할 뿐, 방향을 바꾸지 못한다.

4. Hard 피험자: feature가 이미 hard-like → 정확도 상승.
   Easy 피험자: feature가 hard-like로 이동 → 자신의 특성과 멀어져 정확도 하락.

해결하려면 "불균형 자체"를 고쳐야 한다 — 예를 들어 도메인 손실에 클래스
가중치(hard: ×7.05)를 부여하거나, hard 샘플에만 도메인 손실을 적용하는
one-sided DANN이 필요하다. lambda 튜닝으로는 해결 불가능하다.


[v1~v20 전체를 관통하는 결론]

v18~v20 세 버전의 DANN 계열 시도에서 전체 정확도가 v8을 단 한 번도 넘지
못했다(v18: 59.10%, v19: 62.27%, v20: 63.00% vs v8: 68.69%).

  v18: subject embedding 제거 → 전체 정보 손실 → 최악
  v19: subject embedding 유지 + 이진 DANN → hard 역대 최고, easy 폭락
  v20: lambda 축소 → 방향은 같고 속도만 다름 → gap 역전 구조적으로 확인

이 결과는 단순 lambda 조정으로 해결되지 않는다. DANN 계열을 더 추진하려면
클래스 가중치 보정이 필요하지만, v18~v20 세 버전에 걸친 수익체감 패턴을
감안하면 방향 전환이 더 합리적이다.

현재까지 50클래스 기준 최고는 v9/v10(69.07~69.10%)이며, v20은 추천 모델로
채택하지 않는다.


[향후 개선 후보 (v20 시점까지 미착수)]

- DANN 계열 마지막 시도: 도메인 손실에 클래스 가중치(hard ×7) 적용 →
  불균형 보정. 단 DANN 계열 4번째 시도가 되므로 신중하게 결정 필요.
- 40명 개별 모델 학습 후 평균 정확도로 baseline(82.7%)과 진짜 동일 조건 비교
  (v9부터 계속 미뤄지는 항목). 이 숫자가 나와야 "풀링의 손해"를 정량화 가능.
- 데이터 증강: hard 피험자 신호를 합성/노이즈 추가로 증강해 학습 데이터 보강.
- 에포크 수 증가: v20 val_f1이 30 에포크 내내 상승(체크포인트 ep29). 50 에포크
  시도 시 추가 개선 가능성 있으나 근본 한계는 변하지 않음.
