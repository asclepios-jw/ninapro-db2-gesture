지난 미팅은 v40 시점(단일 모델 70.35%)이었고, 지금은 v55입니다.
이 문서는 "전체 요약"이 아니라 "그때 대비 무엇이 달라졌나"만 정리합니다.


────────────────────────────────────────────────────────────────────────────
한 줄 요약
────────────────────────────────────────────────────────────────────────────
  v40: "단일 모델 70.35%가 우리 성능" 이라고 봤음.
  v55: (1) 앙상블로 프레임 73.0% 돌파,
       (2) ★ "73%는 실제 성능이 아니었다" — 평가 단위를 바로잡으니 표준 88.0%,
       (3) 실시간~표준을 잇는 '정직한 성능 계층'을 확립.
  → 숫자도 올랐지만, 더 큰 변화는 "성능을 어떻게 읽어야 하는가"에 대한 인식.

────────────────────────────────────────────────────────────────────────────
가장 큰 변화 3가지 (미팅에서 강조할 것)
────────────────────────────────────────────────────────────────────────────
① 앙상블이라는 새 레버 (+2.7p)
   · v40까지는 단일 모델 튜닝이 0.1p 단위로 정체(70.3~70.6%).
   · 여러 모델의 확률을 평균내니 73.0%로 돌파 — 재학습 없이 추론만으로.
   · 이것이 v40 이후 "성능을 올린" 가장 큰 요인.

② ★ "73%는 실제 성능이 아니었다" — 평가 단위 재해석 (가장 중요한 변화)
   · v40에선 프레임(윈도우 하나씩) 점수만 봤고, 낮은 macro-F1을 신호 한계로 추정.
   · v49~50에서 클래스 재균형으로 고치려다 실패 → 원인이 편향이 아님을 확인.
   · v51에서 '제스처 실행 단위'로 다수결하니 88.0%, macro-F1 0.85로 급등.
     경계의 순간 오류(잠깐 rest로 튐)가 상쇄되기 때문.
   · 즉 모델 판별력 자체는 충분했고, 문제는 '어떻게 채점하느냐'였다.

③ 정직한 성능 계층 확립
   · 실시간(프레임)부터 표준(동작단위)까지 시나리오별 성능을 한 줄로 정리:
       프레임 73.0% → 온라인 평활 78.6% → 실제 분할 80.4% → (표준) 88.0%
   · "우리 실제 성능은 최소한의 시간 처리만으로 80%대"라고 정직하게 말할 수 있게 됨.
   · 모두 '균일'(개인 데이터·라벨 0) 유지.


────────────────────────────────────────────────────────────────────────────
새로 확정된 것 vs 새로 배제한 것
────────────────────────────────────────────────────────────────────────────
  [새로 확정된 유효 레버]
   · 앙상블(+2.7p), 시간영역/주파수영역 특징(hard/easy 상보적 개선).
   · 시간 후처리(평활·분할·학습 보정)로 실사용 성능을 80%대까지 회수.

  [새로 확정된 막다른 길 — "안 통한다"가 명확해짐]
   · 용량 확대(파라미터↑): 무효. · 전극 shift 증강: 역효과.
   · hard 별도 처리: 무효 + 배포 부담. · macro-F1 클래스 재균형: 무효.
   · 약한 다른-아키텍처 앙상블 멤버: 무효(다양성엔 강도 하한).
   · 반전: 단독 실패한 모델도 앙상블 멤버로는 유용 → "실패 ≠ 무가치".


────────────────────────────────────────────────────────────────────────────
방법론 엄밀성 — 외부 검토(MiniMax) 반영 (v40엔 없던 것)
────────────────────────────────────────────────────────────────────────────
  · "macro-F1이 신호 상한이라는 결론은 성급" → 평가 단위 재해석(88% 발견)을 촉발.
  · "pooled 앙상블(73%)을 개인적응 단일(70.6%)과 비교는 부당" → 동일 조건 비교로 정정.
  · "+0.1p 이득 다수는 노이즈, hard/easy 코호트는 순환성 우려" → 과대주장 정정.
  → 자기 검토로 놓친 사각지대를 외부 검토가 잡음(방법론 신뢰도↑).


────────────────────────────────────────────────────────────────────────────
정리: v40 → v55, 무엇이 달라졌나
────────────────────────────────────────────────────────────────────────────
  · 숫자: 단일 70.35% → 앙상블 프레임 73.0% / 표준 동작단위 88.0%.
  · 인식: "70%가 천장" → "평가 단위를 바로잡으면 88%, 실사용은 80%대".
  · 방법: 단일 모델 튜닝 → 앙상블 + 도메인 특징 + 시간 후처리 + 외부 검토.
  · 태도: 성능 과장 없이 실시간~표준을 2층으로 정직하게 보고.
  한 줄: "아키텍처가 방향을(이전), 앙상블이 천장을, 평가 단위 재해석이
          우리의 진짜 성능을 드러냈다(이후)."
