================================================================
v7 — "더 강한 구조 + 데이터 증강이면 더 좋아지지 않을까": 그러나 기대에 못 미친 결과
================================================================

[이 버전을 시작한 계기]

v6에서 손실 함수 버그를 고치고 67.79% / Macro-F1 55.99%로 지금까지 최고 성능을
냈다. 여기서 더 끌어올릴 수 있을지 확인하기 위해, v6의 검증된 레시피(피험자
임베딩 + attention + CrossEntropy with label smoothing + val macro-F1 기준
체크포인트)는 그대로 유지한 채, 두 가지를 추가로 시도했다:
1) CNN 백본을 TCN(Temporal Convolutional Network)으로 교체
2) 학습 데이터에 노이즈/스케일 증강(augmentation) 추가


[구조 설명 1: TCN 백본 (openclaw/models_v7.py)]

기존(v1~v6)에 쓰던 CNN은 단순히 Conv1d를 2~3겹 쌓고 그 사이에 MaxPool로 시간
축을 줄여나가는 구조였다. v7은 이를 TCN(Temporal Convolutional Network)으로
바꿨다. TCN의 핵심은 "dilated causal convolution"이다.

- Dilation(확장 간격): 일반 컨볼루션은 바로 옆에 붙은 샘플끼리만 묶어서 계산하지만,
  dilation을 주면 듬성듬성 떨어진 샘플들을 묶어서 계산한다. TemporalConvNet에서
  레이어가 깊어질수록 dilation_size = 2^i (1, 2, 4, ...)로 점점 넓어지도록
  설계되어 있어서, 층을 쌓을수록 한 번에 보는 시간 범위(receptive field)가
  기하급수적으로 늘어난다. 즉 적은 레이어 수로도 넓은 시간 구간의 패턴을 볼 수 있다.
- Chomp1d: dilated conv를 쓰면 출력 길이를 입력과 맞추기 위해 패딩을 넣어야 하는데,
  이 패딩이 "미래 정보가 새어 들어오는" 효과를 만들 수 있다. Chomp1d는 출력 끝부분의
  패딩만큼을 잘라내서, 이 모델이 항상 "현재와 과거 정보만" 사용하도록(causal하게)
  강제한다. (참고: 이 프로젝트는 실시간 스트리밍 예측이 아니라 이미 잘라낸 200ms
  윈도우 전체를 한 번에 보는 구조라 causal 제약이 실익은 크지 않지만, TCN 표준
  구현을 그대로 가져온 것으로 보인다.)
- TemporalBlock: Conv1d → Chomp → BatchNorm → ELU → Dropout 을 두 번 반복하고,
  입력을 그대로(혹은 1x1 conv로 채널 수를 맞춰서) 더해주는 residual 연결을 포함한다
  (v5의 ResBlock과 같은 아이디어).
- 전체 구조: TCN(채널 64→128) → MaxPool(시간축 축소) → 피험자 임베딩 결합 →
  Bi-LSTM → Attention(v4/v6과 동일) → 분류기.

TCN을 쓰기로 한 이유: 일반 CNN보다 적은 레이어로 더 넓은 시간 범위를 보고,
LSTM에 넘기기 전에 이미 더 풍부한 시간적 컨텍스트를 담은 특징을 만들어 줄 수
있을 것이라는 기대였다.


[구조 설명 2: 데이터 증강 (openclaw/train_cnn_v7.py의 augment_emg)]

train 배치에만 적용되는 두 가지 증강을 추가했다:
  noise = 가우시안 화이트 노이즈 (std=0.01)
  scale = 채널별로 다른 무작위 스케일 (평균 1.0, std=0.05)
  x_aug = x * scale + noise

의도: 실제 측정 환경에서는 전극 접촉 상태나 미세한 잡음이 매번 조금씩 달라진다.
학습 중에 인위적으로 약한 노이즈와 스케일 변화를 더해주면, 모델이 그런 미세한
변동에 덜 민감해지고(더 강건해지고), 결과적으로 새로운 사람/새로운 시도에 대한
일반화 성능이 좋아질 것이라는 기대로 추가했다.


[학습 설정]

v6의 검증된 학습 레시피를 그대로 따랐다: CrossEntropyLoss(label_smoothing=0.1),
체크포인트는 val macro-F1 최고 기준, epochs=35(v6보다 5 늘림), patience=7(v6보다 1
늘림). weight_decay는 1e-4(v1/v2/v6)에서 1e-3으로 10배 늘렸다 — 모델 용량이 커지고
augmentation까지 추가된 만큼 정규화를 더 강하게 줄 필요가 있다고 판단한 것으로 보임.
추가로 gradient clipping(max_norm=1.0)도 새로 적용했다 — TCN+LSTM 조합은 기울기가
불안정해질 수 있어 학습 안정성을 위한 일반적인 안전장치다.


[v7 결과 — 그리고 의외의 발견]

| 모델                                       | Test Acc | Test Macro-F1 | Weighted-F1 | 학습시간   |
|---------------------------------------------|----------|----------------|-------------|------------|
| v7 (TCN+LSTM+Attention+Augmentation)        | 67.56%   | 55.50%         | 65.98%      | 12,414s    |
| (비교) v6 (CNN+LSTM+Attention)              | 67.79%   | 55.99%         | 66.17%      | 4,260s     |

35 epoch을 전부 다 채워서(조기 종료 없이) 끝났는데도, v6보다 accuracy -0.23p,
macro-F1 -0.49p로 오히려 아주 근소하게 더 낮은 결과가 나왔다. 학습 시간은 v6의
약 3배(12,414s vs 4,260s)나 걸렸다.

학습 곡선을 보면 마지막 epoch(35)의 train accuracy가 81.31%인데 val accuracy는
69.07%로, train-val 격차가 12p 가까이 벌어져 있다. 즉 모델이 train 데이터에는
점점 더 잘 맞아가는데 val 성능은 한참 전(epoch 20~22 근처)부터 거의 정체되어
있었다 — 데이터 증강과 weight_decay 10배 증가라는 두 겹의 정규화를 추가했음에도
여전히 과적합 신호가 뚜렷하다.


[왜 더 복잡한 구조가 더 좋은 결과로 이어지지 않았는가 — 분석]

1. 윈도우 길이가 너무 짧다: 이 프로젝트의 입력은 200ms(=2000Hz 기준 400 샘플) 윈도우
   다. TCN의 dilated convolution이 강점을 보이는 영역은 보통 훨씬 긴 시퀀스(수천
   샘플 이상)에서 멀리 떨어진 시점 간의 의존관계를 잡아낼 때다. 400 샘플짜리 짧은
   윈도우에서는 TCN이 가진 "넓은 receptive field"라는 장점을 충분히 살릴 기회가
   적었을 가능성이 크다 — 오히려 파라미터만 늘어나 과적합 위험만 키운 셈일 수 있다.
2. 데이터 증강이 v2의 정규화 효과와 부분적으로 충돌할 수 있다: v2에서 피험자별
   z-score 정규화를 도입한 핵심 목적이 "사람마다 다른 신호 진폭 차이를 제거하는"
   것이었는데, v7의 random scale augmentation(평균1, std=0.05)은 학습 중에 다시
   진폭을 무작위로 흔들어버린다. 두 메커니즘의 목적이 부분적으로 상충되어, 증강이
   기대한 만큼의 일반화 효과를 주지 못했을 수 있다.
3. v6 자체가 이미 이 데이터/레이블 설정(200ms 윈도우, 40명 풀링, 50클래스)에서
   CNN+LSTM+Attention 조합으로 낼 수 있는 성능에 거의 근접해 있었을 가능성도
   있다 — 즉 "구조를 더 복잡하게 만든다고 항상 더 좋아지는 것은 아니다"라는,
   v3~v5에서 이미 한 번 확인했던 교훈이 v7에서 다른 형태로 재확인된 셈이다.

중요한 점: v7은 "실패"라기보다 "유의미한 음성 결과(negative result)"다 — TCN과
augmentation이라는 합리적으로 보이는 두 가지 개선 아이디어를 실제로 검증해본
결과, 이 특정 데이터/문제 설정에서는 효과가 없거나 오히려 약간 해로울 수 있다는
것을 실험적으로 확인했다는 의미가 있다.

[비용 원장: 시간/디스크/GPU]

  데이터셋 디스크   : 추가 없음 (v2~v6과 동일 데이터)
  결과물 디스크     : openclaw/results_v7, 3.6MB
  학습 시간         : 12,414s (35 epoch 전부 소진, 조기 종료 없음, 약 3.4시간) —
                      v6(4,260s)의 약 2.9배. 이 프로젝트에서 가장 오래 걸린 학습.
  GPU 메모리        : 정확히 측정하지 않음 — RTX 2070 8GB 한도 내에서는 문제없었음


[학습 중 예상치 못하게 발생한 문제들 — 버전/환경/하드웨어]

코드 버그나 라이브러리 버전 문제는 없었지만, 자원/시간 측면에서 예상과 다른
점이 두 가지 있었다:

1. 학습 시간이 기대보다 훨씬 길었다: TCN+LSTM+Attention 구조에 데이터 증강까지
   추가했으니 v6보다 느릴 거라고는 예상했지만, 실제로는 12,414초(약 3.4시간)로
   v6(4,260초, 약 1.2시간)의 거의 3배가 걸렸다. RTX 2070 8GB로는 끝까지 돌리는
   데 문제는 없었지만, "구조를 더 복잡하게 만들면 시간이 좀 더 걸릴 것"이라는
   정도의 예상을 크게 웃도는 비용이었다 — 이 정도 비용 대비 효과(오히려 v6보다
   소폭 하락)였다는 점에서, 사전에 작은 규모로 시간 대비 효과를 먼저 가늠해보고
   본 학습에 들어갔다면 시간을 아낄 수 있었을 것이다.
2. 35 epoch을 전부 다 채우고도 조기 종료가 걸리지 않았다 — patience=7로 v6보다
   여유를 더 줬는데, train accuracy는 계속 오르고 val accuracy는 epoch 20~22
   근처부터 거의 정체된 상태로 끝까지 갔다. 이는 과적합이 진행되고 있는데도
   early stopping 기준(val macro-F1)이 미세하게라도 계속 갱신되면서 조기
   종료를 트리거하지 않은 경우다 — patience 값을 늘릴수록 이런 "사실상 정체인데
   학습을 계속 끄는" 비효율이 발생할 수 있다는 걸 보여준 사례.

하드웨어 자원(GPU 메모리, RAM, 디스크) 자체가 부족해서 문제가 된 적은 없었다 —
순수하게 "시간"이 예상보다 많이 들었다는 것이 이번 버전의 환경 관련 교훈이다.

현재까지(v1~v7) 최종 1위는 여전히 v6이다. 전체 프로젝트를 관통하는 가장 중요한
교훈은: 성능을 끌어올린 변화는 (1) 피험자별 정규화(v1→v2, 딥러닝 모델에서),
(2) 피험자 ID 임베딩(v2→v6 비교 시), (3) 손실 함수를 단순하고 검증된 것으로
되돌린 것(v5→v6)이었고, 반대로 (1) 클래스 불균형 보정 기법의 중첩(v3~v5),
(2) 구조를 무작정 더 복잡하게 만든 것(v7)은 기대만큼의 효과를 주지 못했거나
오히려 해로웠다는 것이다. "더 복잡한 모델 = 더 좋은 성능"이 아니라, 각 변경의
효과를 하나씩 분리해서 직접 검증하는 태도가 이 프로젝트 전체에서 가장 중요했던
작업 방식이었다.


[향후 개선 후보 (v7 시점까지 미착수, v6.txt와 동일)]

- 40명 개별 모델 학습 후 평균 정확도로 단일 피험자 baseline(82.7%)과 동일 조건 비교.
- v6/v7에 안전한 수준의 클래스 불균형 보정 재도입 (rest 다운샘플링, 약한 가중치 등)
  후 rest recall을 모니터링하며 재시도.
- 도메인 적응(DANN, MMD)으로 풀링 모델 일반화 추가 개선.
- 하이퍼파라미터 튜닝(Optuna), 더 짧은/긴 윈도우 길이 비교 실험.
- E2(취약 그룹) 전용 추가 특징/아키텍처 보강.
