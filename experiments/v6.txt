================================================================
v6 — 원인 진단 완료, 버그 수정: 지금까지 만든 모델 중 최고 성능
================================================================

[이 버전을 시작한 계기 — 마침내 원인을 제대로 분석하다]

v3/v4/v5에서 아키텍처를 계속 바꿔봤지만 rest 클래스 recall이 항상 0.0001~0.0002
수준으로 붕괴되어 있었고, accuracy도 30~33%대에 머물렀다(v2: 64.14%). 세 버전의
공통점은 단 하나, 손실 함수 설계였다. 이번 버전에서는 본격적으로 "왜 이 손실
함수 조합이 rest 클래스를 죽이는가"를 끝까지 분석했다.

원인 분석 (정확한 메커니즘):
1. rest 클래스는 train 데이터의 약 43%를 차지한다. inverse-frequency 방식의
   class weight는 "빈도의 역수"를 가중치로 쓰기 때문에, 가장 많이 등장하는 rest에는
   극단적으로 작은 가중치가 매겨진다. (예를 들어 다른 클래스 대비 수십 배 작은 값.)
2. 여기에 Focal Loss의 (1-pt)^gamma 항이 추가로 곱해진다. 이 항은 "모델이 이미 잘
   맞히는(쉬운) 샘플"의 손실을 깎아주려고 설계된 것인데, rest는 신호가 거의 없는
   상태라 원래 분류하기 쉬운 클래스다. 즉 rest는 "원래도 쉬워서 (1-pt)^gamma가 작고",
   "class weight도 작다" — 두 메커니즘이 같은 방향(rest의 손실을 줄이는 방향)으로
   동시에, 중첩되어 작용한 것이다.
3. 결과적으로 rest 클래스는 손실 계산에서 거의 무시되는 수준까지 억제되었고,
   모델은 "rest를 맞혀도 손실이 거의 안 줄어드니, rest라고 답할 이유가 없다"는
   방향으로 학습이 수렴해버렸다. rest를 거의 예측하지 않으니 recall이 0에 가깝게
   떨어졌고, rest가 test set의 43.2%를 차지하므로 전체 accuracy도 같이 폭락했다.
4. 부차적인 원인: 체크포인트를 val_loss가 가장 낮은 지점으로 선택했는데, 이미
   손실 함수 자체가 왜곡된 상태이므로 "val_loss가 낮다"는 것이 "실제로 좋은 모델"을
   의미하지 않게 되어버렸다. 즉 잘못된 손실 지형에서 "그 지형 안에서만 좋아 보이는"
   지점을 고르는 이중의 오류가 있었다.

교훈: 클래스 불균형 보정 기법(class weight, focal loss 등)을 여러 개 동시에 강하게
적용하면, 서로 효과가 상쇄되는 게 아니라 같은 방향으로 중첩되어 역효과를 낼 수
있다. 이런 기법을 적용한 뒤에는 반드시 다수 클래스의 recall과 전체 accuracy를
함께 모니터링해야 한다는 것이 이번 사고에서 얻은 핵심 교훈이다.


[수정 내용: openclaw/models_v6.py, openclaw/train_cnn_v6.py]

v6는 "아키텍처는 그대로 둔 채 의심되는 부분만 정확히 바꿔서" 진짜 원인이 손실
함수였는지 검증하는 실험으로 설계했다. 아키텍처는 v4 기준(SubjectAwareCNNLSTM
+ Attention)을 그대로 유지했다 — ResNet 백본(v5)은 가져오지 않았다, 왜냐하면
v4→v5의 개선폭이 미미했고, 이번 실험의 목적은 "손실 함수 수정만으로 얼마나
회복되는지"를 깨끗하게 보기 위함이었기 때문이다 (변수를 하나만 바꿔서 비교하는
원칙을 지키기 위한 선택).

바뀐 것은 정확히 두 가지:
1. FocalLoss + inverse-frequency class weight → CrossEntropyLoss(label_smoothing=0.1)
   (v1/v2에서 이미 안정적으로 잘 작동했던, 검증된 손실 함수로 되돌림)
2. 체크포인트 선택 기준: val_loss 최저 → val macro-F1 최고
   (이제는 손실 값이 아니라, 우리가 실제로 신경 쓰는 지표인 macro-F1을 기준으로
   "가장 좋은 모델"을 고르도록 변경 — 손실 지형이 아니라 목표 지표를 직접 본다.)

추가로 학습 강도도 v1/v2와 동일하게 맞췄다(epoch 30 + early stopping patience=6).
v3~v5는 epoch 20으로 짧게 돌렸었는데, v6에서는 "공정한 비교"를 위해 v1/v2와
같은 학습 강도로 통일했다.


[v6 결과]

| 모델                                  | Test Acc | Test Macro-F1 | Test Weighted-F1 | 학습시간 |
|----------------------------------------|----------|----------------|--------------------|----------|
| v6 (SubjectAware+Attention, fixed)     | 67.79%   | 55.99%         | 66.17%             | 4260s    |

v2(64.14% / 48.48%) 대비 Acc +3.65p, Macro-F1 +7.51p — 지금까지 만든 모든 모델
(v1, v2, openclaw v3~v5) 중 최고 성능이다.

이 결과로 두 가지가 동시에 입증됐다:
1. v3~v5에서 추가했던 "피험자 ID 임베딩 + attention" 아이디어 자체는 처음부터
   유효한 방향이었다. 다만 손실 함수 버그에 가려져서 그동안 그 효과를 전혀
   확인할 수 없었던 것뿐이다.
2. 손실 함수만 정상으로 되돌리자, 가려져 있던 효과가 곧바로 드러났다 —
   v2(64.14%)보다도 더 높은 성능이 나온 것은 피험자 임베딩+attention이 실제로
   순효과(net positive)를 만들어내고 있었다는 뜻이다.

[학습 중 예상치 못하게 발생한 문제들 — 버전/환경/하드웨어]

v6 자체의 학습 과정에서는 버그나 환경 문제가 없었다 — 변경 범위를 "손실 함수와
체크포인트 기준만"으로 의도적으로 좁혔기 때문에 새로운 코드 경로가 거의
없었고, 그만큼 새로운 사고가 날 여지도 적었다.

대신 이번 버전에서 가장 크게 "예상과 달랐던" 부분은 결과의 방향 자체였다:
손실 함수를 고치면 "v3~v5의 문제가 어느 정도 완화되겠지" 정도로 예상했는데,
실제로는 v2(64.14%)보다도 더 높은 성능(67.79%)이 나왔다. 즉 단순히 "버그를
없앤 것"을 넘어서, 그동안 버그에 가려져 있던 피험자 임베딩+attention의 순효과가
기대보다 훨씬 크게 드러난 것이다 — 나쁜 의미의 "예상과 다름"이 아니라 좋은
의미의 깜짝 결과였다.

하드웨어 자원 문제는 없었다 — epoch 수를 v3~v5의 20에서 v1/v2와 같은 30으로
늘렸지만(+ patience=6 조기 종료), RTX 2070 8GB로 충분히 끝까지 돌았다.

(부록: 학습 자체와는 무관하지만, v6 결과를 정리하던 중 결과 폴더 이름이
"results_v6(claude)"로 자동 생성된 일이 있었다. openclaw와 Claude가 같은
경로에 동시에 접근할 때 충돌을 피하려고 시스템이 자동으로 접미사를 붙인
것이었는데, 처음엔 이를 실수로 보고 "results_v6"로 이름을 바꿨다가, 사용자가
"그 접미사는 작업 주체를 구분하려고 직접 붙인 명명 규칙"이라고 알려줘서
다시 원래대로 되돌렸다. 작은 일이지만 "이름이 이상해 보인다고 바로 정리하지
말고, 먼저 의도가 있는지 확인하는" 습관이 필요하다는 걸 보여준 사례였다.)

[종합 결론]

1. 현재까지 최선의 모델은 v6 — 피험자 ID 임베딩 + attention pooling + 정상적인
   손실 함수(CrossEntropy + label smoothing)의 조합.
2. 단일 피험자 baseline(82.7%) 대비 격차(67.79%)는 여전히 크지만, v1/v2(60%대)
   보다는 확실히 좁혀졌다 — "피험자 정보를 모델에 명시적으로 주입한다"는 방향이
   옳았음을 v6에서 확인했다.
3. 클래스 불균형 보정(class weight, focal loss 등)은 잘못 쓰면 정규화나 아키텍처
   개선보다 훨씬 크게 성능을 깎을 수 있다 — 적용할 때는 반드시 다수 클래스의
   recall과 전체 accuracy를 함께 모니터링하고, 체크포인트는 raw loss가 아니라
   목표 지표(macro-F1 등)로 선택해야 한다.


[이 버전 이후 — 향후 개선 후보 (v6 시점까지 미착수)]

- 40명 개별 모델을 따로 학습해 평균 정확도를 내고, baseline(82.7%)과 진짜 동일한
  조건으로 비교해보기.
- v6에 안전한 수준의 클래스 불균형 보정을 다시 도입해보기 (예: rest 다운샘플링,
  또는 더 약한 가중치 + gamma를 낮춘 focal loss) — 이번에는 rest recall을
  계속 모니터링하면서 조심스럽게 재시도.
- 도메인 적응(DANN, MMD) 같은 기법으로 풀링 모델의 일반화 성능을 추가로 개선.
- 하이퍼파라미터 튜닝(Optuna), 데이터 증강.
- E2(취약 그룹) 전용 추가 특징이나 아키텍처 보강.

(참고: 이후 시도된 v7(TCN+LSTM+Attention+데이터 증강)은 이 흐름 정리 작업 시점에
아직 학습이 진행 중이라 이 문서에는 포함하지 않았다. 완료되면 별도 문서로 정리할 것.)
