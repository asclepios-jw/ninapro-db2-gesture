================================================================
v40 정리: 팀 원본 전처리 vs v40 전처리 차이 + v40 파이프라인 구조
Ninapro DB2 · sEMG 제스처 분류 · 현재 최고 v40 = 70.35%
================================================================


================================================================
1. 팀 원본 전처리 vs v40 전처리 데이터 차이
================================================================

  팀 원본  = 전처리전달/       (v25, 62.58%)
  v40 사용 = 전처리전달_v28/   (v28 방식)

차이는 두 단계 변경이 누적된 것:
  ① 필터 변경 (v27) + ② 정규화 순서 변경 (v28)


── ① 포락선(envelope) 필터 ─────────────────────────────────────

  항목                        팀 원본     v40 (v28)
  ──────────────────────────  ─────────   ─────────
  포락선 lowpass 차단주파수    5 Hz        10 Hz
  포락선 필터 차수             2차         4차

  → 10Hz/4차는 포락선이 더 빠른 근육 활성 변화를 담고(5Hz는 과하게
    뭉갬), 필터 롤오프가 더 날카로움. 이 변경만으로 +0.98p (v27).

  공통(안 바뀐 것): bandpass 20–500Hz, notch 50Hz, 창 300ms,
  stride 150ms, purity 0.8, 분할 rep1-4 / rep5 / rep6.


── ② 정규화 순서 (데이터를 가장 크게 바꾼 부분) ────────────────

  팀 원본 순서:
    필터 → |raw 필터EMG| → 포락선(12ch) → EMG+포락선 24ch 쌓기
    → 윈도우 → 24ch 전체 정규화(피험자별)
    · 포락선을 "원본 EMG"에서 계산한 뒤, EMG·포락선 24채널을 함께 정규화
    · 결과: 포락선도 정규화됨 → 24채널 모두 zero-mean

  v40(v28) 순서:
    필터 → EMG 12ch 정규화(연속신호, train rep) → |정규화된 EMG|
    → 포락선(12ch) → 24ch 쌓기 → 윈도우
    · EMG를 먼저 정규화한 뒤, 그 정규화된 EMG에서 포락선 계산
    · 포락선은 따로 정규화하지 않음 (이미 정규화된 신호에서 나왔으므로)

  → 이 변경으로 +1.13p (v28).


── 실제 데이터 통계 비교 (측정값) ──────────────────────────────

                          팀 원본(전처리전달)   v40(전처리전달_v28)
  전체 mean / std          -0.029 / 0.93        0.202 / 0.80
  EMG(0:12) mean / std      0.00  / 0.93        0.00  / 0.94
  포락선(12:24) mean / std  -0.059 / 0.93        0.404 / 0.57
  포락선 범위(min~max)      -1.56 ~ 13.5        -0.36 ~ 13.2

  핵심: 팀 원본은 포락선도 zero-mean(std 0.93)으로 정규화됐지만,
  v40은 포락선이 양수 쪽으로 치우침(mean 0.40). 포락선은 |값|에서
  나와 원래 양수인데, v40은 이걸 정규화로 지우지 않고 그대로 둔 것.
  (이 non-zero mean은 v32에서 지적된 특성이며, "24ch 공동 정규화"가
  향후 개선 후보로 남아 있음.)


── 정규화 통계 저장 방식 차이 ──────────────────────────────────

  팀 원본 : norm_mean/std (41,24)에 피험자별 실제 통계 저장
            (실제 X 데이터에는 이미 정규화가 반영됨)
  v40(v28): 정규화를 전처리 단계에서 데이터에 직접 구워넣음
            → norm_mean=0, norm_std=1 (항등, 학습 시 추가 정규화 없음)


── 요약: 팀 원본 → v40 전처리 차이 총정리 ──────────────────────

  1. 포락선 lowpass: 5Hz → 10Hz
  2. 포락선 필터 차수: 2차 → 4차
  3. 정규화 대상 순서: (포락선을 raw에서 계산 후 24ch 정규화)
     → (EMG 먼저 정규화 후 그로부터 포락선 계산, 포락선은 미정규화)
  4. 정규화 시점: 윈도우 후(post-windowing) → 연속신호(pre-windowing)
  5. 결과 분포: 24ch 모두 zero-mean → 포락선만 양수 치우침(mean 0.40)
  6. norm 통계 저장: 실제 통계 보관 → 항등(0/1, 데이터에 구워넣음)

  성능 기여(단순 아키텍처 기준): 필터 +0.98p, 정규화 순서 +1.13p.


================================================================
2. v40 파이프라인 전체 구조
================================================================

v40 = 전처리 → 1단계 pooled 학습 → 2단계 피험자별 적응형 fine-tuning
      의 3층 구조.


┌─ 0. 데이터 (전처리전달_v28) ──────────────────────────────┐
│  raw sEMG 12ch (Ninapro DB2, 2kHz)                        │
│   → bandpass 20-500Hz + notch 50Hz                        │
│   → EMG 12ch 피험자별 정규화 (연속신호, train rep 통계)    │
│   → |정규화 EMG| → 10Hz/4차 lowpass → 포락선 12ch          │
│   → 24ch 쌓기 → 300ms 창(600샘플)/150ms stride, purity 0.8 │
│   → 분할: rep1-4 학습 / rep5 검증 / rep6 테스트            │
└───────────────────────────────────────────────────────────┘
                       │ (N, 600, 24)
                       ▼
┌─ 아키텍처: SubjectAwareCNNLSTMAttention (models_v8) ──────┐
│  CNN: Conv k5→BN→ELU→Pool, Conv k3→BN→ELU→Pool            │
│       (24→128채널, 시퀀스 600→150)                        │
│  + subject embedding(41x32)를 매 타임스텝 CNN 출력에 연결  │
│  BiLSTM(128+32 → 128, 2층, 양방향)                         │
│  Attention(tanh+Linear 비선형) 풀링 → context 256          │
│  Dropout(0.4) + Linear(256→50)                            │
│  파라미터 수: 805,266                                      │
└───────────────────────────────────────────────────────────┘
                       │
        ┌──────────────┴───────────────┐
        ▼                               ▼
┌─ 1단계: Pooled 학습 ──────────┐
│  40명 전체 한 번에             │
│  강한 증강(GPU 온라인, 배치마다):│
│   · magnitude warp σ0.30       │
│   · time warp σ0.25            │
│   · jitter σ0.06               │
│   · mixup α0.30                │
│  손실: Focal Loss (γ2)         │
│  AdamW 1e-3, Cosine 50ep,      │
│  batch 256                     │
│  → best_model_v40.pth          │
│  = 70.05% (pooled 단독,        │
│    단일 모델 최초 70% 돌파)    │
└───────────────┬────────────────┘
                ▼
┌─ 2단계: 적응형 per-subject fine-tuning ──────────────────┐
│  피험자 40명 각각에 대해:                                 │
│   1) v40 base 체크포인트 로드                             │
│   2) CNN backbone 동결(freeze_cnn),                       │
│      LSTM + attention + subject_emb + fc 만 학습          │
│      (Adam 1e-4, 15ep, 증강 없음)                         │
│   3) 검증 macro-F1로 fine-tuned vs base 중 나은 것 선택   │
│      (fine-tuning이 해로운 피험자는 base 유지)            │
│  → 40명 결과 종합: 70.35% (FT 36명 / BASE 4명)            │
└───────────────────────────────────────────────────────────┘


── 설계 원리 세 가지 ───────────────────────────────────────────

  1. 증강(1단계)은 backbone을 개선 → 공통 특징을 일반화.
     과적합을 없애 base를 끌어올림.

  2. fine-tuning(2단계)은 상위 레이어만 개인화 → CNN은 동결해 공통
     특징 보존, 피험자별 스타일은 LSTM/attention/embedding으로 적응.

  3. 이 둘은 역할이 달라 상보적 — 그래서 증강을 강화해도(v40)
     fine-tuning 이득이 살아남음(FT 36명). 반대로 장기학습(상위
     레이어까지 최적화)은 fine-tuning과 경쟁해 손해였음(v39).

  즉 v40 = "강한 증강으로 공통 backbone을 최대한 키우고, 그 위에
  피험자별 개인화를 안전하게(adaptive) 얹는다"는 파이프라인.


── 재현 정보 ───────────────────────────────────────────────────

  데이터  : 전처리전달_v28/  (build_dataset_v28.py 출력)
  1단계   : code/train_cnn_v40.py  → results/v40/best_model_v40.pth
  2단계   : code/finetune_v40.py   → results/v40/result_v40.json
  아키텍처: code/models_v8.py (SubjectAwareCNNLSTMAttention)
  결과    : pooled 70.05% / 최종 70.35%
