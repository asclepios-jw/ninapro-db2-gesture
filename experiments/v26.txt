================================================================
v26 — 팀 데이터 + global 정규화 재적용: 62.99% (정규화는 원인이 아님)
================================================================

[이 버전을 시작한 계기]

v25(62.58%)가 v10(69.10%) 대비 -6.52p로 대폭 하락.
데이터 통계 비교(ch-wise std, 분할 크기) 후 이상 없었으나,
train 극단값(|max|=136.92) vs val/test(|max|≈43-45) 분포 불일치 발견.

가설: 전처리 팀의 per-subject 정규화가 원인.
  a) 피험자 간 스케일 차이 제거 → 모델이 암묵적으로 활용하던 신호 손실
  b) train에 이상치 포함 시 per-subject 정규화 후 val/test 분포와 乖離

→ v26: 팀 데이터에 우리 방식(X_train 전체 global mean/std) 재적용.
   정규화가 원인이면 v10 수준 회복, 아니면 데이터 자체의 문제.


[방법: code/train_cnn_v26.py]

아키텍처: v10/v25와 100% 동일.
  Conv1d(24→64,k=3)+BN+ReLU → Conv1d(64→128,k=3)+BN+ReLU
  BiLSTM(128,2L,bidir,dropout=0.3) → Attention → SubjEmb(40,32)
  Dropout(0.4) + Linear(288,50)

정규화 변경:
  v25: 정규화 없음 (팀이 적용했다고 가정, 그대로 사용)
  v26: X_train에서 global mean/std 계산 후 모든 split에 적용
       mean: (1,1,24), mean[0,0,:3]=[1.05e-10, 1.08e-10, 1.92e-10] ≈ 0
       std:  (1,1,24), std[0,0,:3]=[0.8928, 0.8960, 0.9165]

  → std가 1이 아닌 것(≈0.9): 팀 데이터가 "이미 거의 정규화됨"을 의미.
    global재적용시 std≈0.9→1.0 수준 정도의 소폭 조정만 일어남.

데이터: 전처리전달/ (팀 전처리, v25와 동일)
파라미터 수: 705,203 (v10과 동일)
하이퍼파라미터: v10/v25와 동일 (AdamW 1e-3, CosineAnnealingLR, 50ep, patience=8, batch=256)

[기대와 실제가 어떻게 달랐는가]

기대: global norm 재적용으로 v10 수준(69%) 회복 기대.
     정규화가 원인이면 6p 이상 회복.

실제: +0.41p. 거의 변화 없음.

결론: **정규화 방식은 v25 실패의 원인이 아니다.**
      문제는 팀 데이터의 내용(content) 자체.


[원인 분석: 팀 데이터 자체의 문제]

3개 버전 비교로 원인 범위를 좁힘:

  "아키텍처 동일 + 우리 데이터"        → 69.10%  (v10)
  "아키텍처 동일 + 팀 데이터, 정규화A" → 62.58%  (v25)
  "아키텍처 동일 + 팀 데이터, 정규화B" → 62.99%  (v26)

정규화는 변수에서 제외. 팀 데이터의 내용이 -6~7p 차이를 만든다.

가능한 원인:

  1. 전처리 파이프라인 차이
     필터링 방법, 컷오프 주파수, 엔벨로프 계산 방법(e.g. RMS 윈도우 크기)이
     다르면 같은 raw 데이터에서 완전히 다른 특징이 나온다.

  2. 윈도우 분할 방식 차이
     우리: rep 1-4 train, rep 5 val, rep 6 test (rep-based)
     팀:  알 수 없음. 무작위 윈도우 분할이면 평가가 더 엄격(편향 없음)하지만,
         또는 다른 rep 배정이면 v10의 69.10%가 특정 rep 조합에 유리했을 수 있음.

  3. 채널 순서 차이
     12 sEMG + 12 envelope = 24ch. 팀이 다른 순서로 쌓았다면
     Conv1d가 다른 채널 관계를 학습한다.

  4. 데이터 품질 차이
     팀 데이터에 artifact, 세션 오염이 더 많을 수 있음.
     또는 우리 전처리에서 특정 artifact를 제거했는데 팀 전처리에서 유지됨.

  5. 우리 v10의 낙관적 편향
     우리 데이터의 rep 1-4/5/6 분할이 "쉬운 분할"일 가능성.
     팀 데이터가 오히려 더 중립적 평가 기준일 수 있음.


[전략적 결정]

팀 데이터에서 62~63%이 ceiling인지 아직 모름.
   우리 아키텍처 개선 실험들(v23~v24)이 모두 우리 데이터에서 실패했는데,
   팀 데이터에서도 유사하게 실패할 가능성이 높음.

다음 탐색 우선순위:
  1. 팀에 전처리 파이프라인 문서 요청 → 채널 순서, 필터링 파라미터 확인.
  2. 우리 데이터로 계속 아키텍처 개선 후 팀 데이터에서 재검증.
  3. 팀 데이터에서 더 많은 에포크(100ep) 시도 → tr_acc=77.6%이 아직 낮아 언더피팅 가능.


[향후 개선 후보]

1. (즉시) 팀에 전처리 파이프라인 코드/문서 요청.
   채널 순서, 정규화 통계 계산 기준(train only vs all?) 확인.

2. (단기) 팀 데이터에서 에포크 증가 (100ep, patience=15).
   v26의 tr_acc=77.6%이 v10의 tr_acc(~85%)보다 낮아 underfitting 가능성 있음.
   더 학습시키면 성능 개선 여지.

3. (단기) 하드 피험자 oversampling (2~3×) + focal loss 조합.
   v26에서 hard_acc=50.85% — v10 대비 hard 성능이 더 나쁨.
   hard 피험자에 집중한 학습 전략이 더 필요할 수 있음.

4. (장기) 두 전처리 데이터 합산 후 훈련.
   우리 데이터(447k) + 팀 데이터(447k) = ~894k 윈도우.
   더 많은 데이터가 generalization 향상시킬 수 있음.
