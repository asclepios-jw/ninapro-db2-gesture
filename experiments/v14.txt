v14 — 클래스를 단순화하면 어려운 피험자가 더 좋아질까: 부분적으로 맞음

[이 버전을 시작한 계기]

v13에서 "신호를 더 깨끗하게 만드는" 방향(디노이징)이 막힌 길로 끝난 뒤,
v12부터 미뤄두었던 다음 후보 — "separability가 낮은 피험자에게는 클래스
수를 줄인 단순화 태스크를 적용해보자" — 를 시도했다. 신호 자체를 못 고친다면,
문제(태스크) 난이도를 조절하는 쪽으로 접근을 바꿔본 것이다. v9~v13의
원칙을 그대로 이어, 모델을 새로 학습하지 않고 v8 베이스 모델의 예측
결과만으로 검증 가능한 진단부터 설계했다.


[방법: code/diagnose_class_grouping.py]

1) v8 체크포인트로 test set 전체에 대해 추론을 한 번 수행해서, 윈도우마다
   (정답 라벨, 예측 라벨, 피험자 ID)를 얻었다. (정확도 68.69%로 v8 결과와
   정확히 일치 — 추론 파이프라인이 올바르게 재현됨을 먼저 확인.)
2) 이 예측 결과로 50×50 confusion matrix를 만들고, "두 클래스가 얼마나
   자주 서로 혼동되는가"를 유사도로 변환해(confusion 비율의 평균, 대칭화)
   거리 행렬을 만들었다.
3) 이 거리 행렬에 계층적 클러스터링(average linkage)을 적용해서, 50개
   클래스를 더 적은 수의 "상위 클래스(superclass)"로 묶었다 — 자주
   혼동되는 클래스일수록 같은 그룹으로 묶이도록.
4) 정답/예측 라벨을 둘 다 상위 클래스로 변환한 뒤, 그 기준으로 정확도를
   다시 계산했다. 클래스 수를 10/15/20/25개로 바꿔가며 비교.
5) 어려운 5명(S28,S31,S04,S26,S07)과 나머지 35명의 정확도 격차(gap)가
   클래스를 단순화할수록 어떻게 변하는지 추적했다.

  의미 있는 그룹을 찾아냈다는 뜻이다.


[기대와 실제가 어떻게 달랐는가]

기대: "어려운 피험자의 문제는 비슷한 동작들끼리 헷갈리는 것일 수 있으니,
클래스를 단순화하면 그 혼동이 줄어 격차가 좁혀질 것"이라는, 검증되지 않은
가설이었다.

실제: 가설이 **부분적으로 맞았다**. k를 줄일수록(클래스를 더 단순화할수록)
격차가 꾸준히 줄었고, k=10에서는 fine-grained 대비 35.8%나 줄었다. 다만
완전히 사라지지는 않았다 — k=10에서도 여전히 8.19%p의 격차가 남는다. 즉
어려운 피험자의 문제 중 상당 부분(전체 격차의 약 1/3)은 "같은 계열 안에서의
세부 구분이 어렵다"는 것으로 설명되지만, 나머지 2/3는 클래스를 단순화해도
없어지지 않는 더 근본적인 어려움이다 — v12에서 본 "낮은 SNR/separability"가
세부 구분뿐 아니라 큰 카테고리 구분에도 어느 정도 영향을 주고 있다는 뜻으로
해석된다.

v9~v13(전부 효과 없음 또는 역효과)과 비교하면, v14는 이 프로젝트에서
처음으로 "부분적으로나마 명확한 긍정적 신호"가 나온 분석이다.


[학습 중 예상치 못하게 발생한 문제들 — 버전/환경/하드웨어]

코드/환경 문제는 없었다. 굳이 짚을 점은, 클러스터 수(k)를 4개 값(10/15/20/25)
만 시도했다는 것 — 더 세밀한 k 스캔(예: 5~35까지 전부)을 했다면 "격차가
줄어드는 속도가 어디서부터 완만해지는지"를 더 정확히 볼 수 있었을 것이다.
이번엔 빠른 진단이 목적이라 4개 값으로 충분하다고 판단했다.

또한 이 분석은 "50개 클래스를 그대로 두고 추론 결과만 사후에 그룹으로
묶어 평가"한 것이라, **실제로 k=10짜리 분류기를 처음부터 그렇게 학습시킨
것과는 다르다** — 모델이 애초에 10개 클래스만 구분하도록 학습됐다면 지금
추정한 것보다 더 좋은 결과가 나올 수도, 혹은 다른 패턴이 나올 수도 있다.
이번 v14는 "정말로 모델을 다시 학습할 가치가 있는지"를 보기 위한 사전
진단이었다는 것을 분명히 기록해 둔다.


[v1~v14 전체를 관통하는 결론]

v14도 v12/v13처럼 모델을 새로 학습하지 않은 분석 버전이라 메인 순위표에는
추가할 행이 없다. 대신 이번 결론은 분명한 다음 행동을 가리킨다:

  - 어려운 피험자 문제의 약 1/3은 "세부 클래스 구분의 어려움"으로 설명되고,
    나머지 2/3는 더 근본적인 어려움(낮은 SNR/separability)으로 남는다.
  - 클래스 그룹화는 "전부 해결"은 아니지만 "부분적으로 유효한" 첫 번째
    긍정적 신호다 — v9(시차보정), v10(freeze), v11(center loss),
    v13(디노이징)이 전부 무효/역효과였던 것과 대조적이다.
  - 다음 단계로 자연스럽게 이어지는 질문: 이 사후 그룹화 효과가 실제
    학습에도 그대로 나타나는지 — 즉 모델을 k=10(혹은 비슷한 수준)
    클래스로 처음부터 새로 학습시키면 정말로 어려운 피험자의 절대 성능이
    이만큼 올라가는지 확인이 필요하다.


[향후 개선 후보 (v14 시점까지 미착수)]

- (최우선) k=10~15 수준의 상위 클래스로 모델을 처음부터 재학습해서, 사후
  그룹화로 추정한 효과가 실제 학습에서도 재현되는지 검증.
- 클러스터 수(k)를 더 세밀하게 스캔(5~35) 해서 격차 감소가 완만해지는
  지점을 더 정확히 찾기.
- "남은 2/3 격차"의 원인을 더 분석 — 상위 클래스 내부에서도 어려운
  피험자가 유독 더 헷갈리는 특정 클래스 쌍이 있는지 확인.
- 도메인 적응(DANN, MMD) — 클래스 단순화와 결합해서 시도해볼 수도 있음.
- 40명 개별 모델 학습 후 평균 정확도로 baseline(82.7%)과 진짜 동일 조건 비교
  (v9부터 계속 미뤄지는 항목).
