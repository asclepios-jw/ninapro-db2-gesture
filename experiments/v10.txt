================================================================
v10 — "과적합 때문에 분산이 컸던 걸까?": Freeze 강도 어블레이션, 가설 기각
================================================================

[이 버전을 시작한 계기]

v9에서 피험자별 fine-tuning을 전체 네트워크(100% 파라미터)에 적용했더니, 평균
개선(+0.39p)보다 피험자 간 분산(std_acc 7.56%p)이 훨씬 컸다 — 어떤 사람은
+1%p 이상 좋아지고 어떤 사람은 -1%p 이상 나빠졌다. 다른 곳(별도 세션)에서
이를 보고 "피험자당 데이터가 적은데(11,000개) 전체 네트워크를 다 풀어서
학습하면 과적합이 생겨서 분산이 커지는 것 아니냐, CNN 백본을 얼리고
classifier/attention만 학습하면 일반화가 더 안정적으로 될 것"이라는 가설이
제시됐다. 같은 자리에서 Center Loss/Focal Loss 튜닝도 같이 제안됐지만, 사용자가
"이번엔 freeze 가설 하나만 먼저 검증해보자"고 정해서 v10은 이것만 다룬다.


[검증 설계: code/finetune_v10.py]

v9(전체 fine-tune, 100% 파라미터 학습)를 기준선으로 두고, 학습 가능한 파라미터
비율을 인위적으로 줄인 두 가지 모드를 추가로 만들어 비교했다.

  - classifier_only : CNN+LSTM+Attention+피험자임베딩을 전부 얼리고, 마지막
    분류기(fc, Linear)만 학습. 전체 805,266개 파라미터 중 12,850개(1.6%)만 학습.
  - freeze_cnn       : CNN 백본만 얼리고, 피험자 임베딩+LSTM+Attention+분류기는
    그대로 학습. 772,434개(95.9%)가 학습 대상 — v9(100%)와 거의 비슷한 수준.

나머지 설정(epoch=15, patience=5, lr=1e-4, 피험자당 train ~11,000 윈도우, v8
데이터셋 재사용)은 v9와 완전히 동일하게 맞췄다 — 오직 "얼마나 많은 파라미터를
얼리는가" 하나만 바꿔서, 그 변수의 순효과만 보려는 설계였다.


[재현 정보]

  cd ninapro_db2_project/code
  python3 finetune_v10.py --mode classifier_only
  python3 finetune_v10.py --mode freeze_cnn
  # DATA_DIR  = data_processed/v8 (v9와 동일, 재구축 없음)
  # BASE_CKPT = results/v8/best_model_v8.pth (v9와 동일 시작점)
  # OUT_DIR   = results/v10


[비용 원장: 시간/디스크/GPU]

  데이터셋 디스크   : 추가 없음 (v8/v9 데이터 재사용)
  결과물 디스크     : results/v10, json 결과 파일 + 비교 차트 1장 (수 MB 수준)
  학습 시간         : classifier_only 884.5s(40명, 평균 22.1s/명, 학습 파라미터가
                      적어 v9보다 빠름), freeze_cnn 1622.1s(40명, 평균 40.6s/명,
                      v9의 1776.8s와 거의 같음 — 파라미터 5% 차이는 속도에
                      거의 영향이 없었다)
  GPU 메모리        : 정확히 측정하지 않음


[결과]

  방식                         평균 Acc   평균 Macro-F1   std(Acc)   학습시간
  Pooled(v8, fine-tune 없음)    68.68%     57.84%          —          —
  classifier_only (1.6% 학습)   68.36%     57.46%          7.60%p     885s
  freeze_cnn (96% 학습)         69.10%     58.84%          7.56%p     1622s
  v9 전체 fine-tune (100% 학습) 69.07%     58.78%          7.56%p     1777s


[기대와 실제가 어떻게 달랐는가 — 가설 기각]

기대했던 패턴: 학습 가능한 파라미터를 줄일수록(100% → 96% → 1.6%) 과적합이
줄어 평균은 비슷하거나 약간 낮아지더라도 표준편차(분산)는 뚜렷이 작아질 것.

실제로 나온 패턴: 정반대였다.
1. classifier_only(1.6%)는 평균이 fine-tuning을 안 한 base(68.68%)보다도
   더 낮았다(68.36%) — "얼리면 안전하다"가 아니라 "너무 얼리면 표현력이
   부족해서 오히려 손해"였다. 결정적인 동작(이 피험자만의 신호 특성)을
   학습하려면 분류기 레이어 하나로는 용량이 부족했던 것으로 보인다.
2. freeze_cnn(96%)은 v9(100%)와 평균·분산 모두 거의 완전히 같았다
   (acc 69.10% vs 69.07%, std 7.56%p vs 7.56%p — 소수점 둘째 자리까지 일치).
   즉 CNN 백본 하나를 얼리는 정도로는 과적합 양상에 아무 변화도 주지 못했다.
3. 가장 중요한 결론: **분산(std≈7.56%p)은 세 가지 다른 학습 전략(1.6%/96%/100%
   파라미터)에서 거의 변하지 않았다.** 학습 가능한 파라미터 양을 조절해도
   분산이 줄어들지 않는다는 것은, 이 분산이 "모델이 학습 데이터에 과적합해서
   생기는 것"이 아니라 "피험자 본인의 신호 자체가 원래 쉽거나 어렵다"는, 데이터
   쪽에서 오는 근본적인 차이라는 뜻이다. v9에서 봤던 S01/S05/S40(이미 baseline급)
   과 S28/S31(계속 낮음)의 차이는 fine-tuning 전략을 바꿔도 똑같이 반복됐다
   (results/v10/freeze_comparison.png에서 세 선이 거의 같은 모양으로 겹친다).


[학습 중 예상치 못하게 발생한 문제들 — 버전/환경/하드웨어]

코드/환경 문제는 없었다. 굳이 꼽자면, classifier_only가 학습 파라미터는
freeze_cnn의 60분의 1 수준(12,850 vs 772,434)인데도 학습 시간은 884.5s vs
1622.1s로 절반 정도밖에 안 줄었다는 점이 예상과 달랐다 — 옵티마이저가 갱신할
파라미터 수는 줄었지만, forward pass 자체(CNN+LSTM+Attention 전체를 통과시키는
연산)는 freeze 여부와 무관하게 똑같이 수행해야 하기 때문이다. "파라미터를
1.6%만 학습한다고 학습 속도가 1.6%만큼만 든다"는 건 아니라는 것을 보여준
사례 — 연산량(forward pass)과 갱신해야 할 파라미터 수(backward의 일부)는
서로 다른 비용 축이라는 걸 명확히 확인했다.


[v1~v10 전체를 관통하는 결론]

  순위   모델 (버전)                                      Test Acc   Test Macro-F1
  1      v10-freeze_cnn (96% 파라미터 fine-tune)           69.10%     58.84%
  2      v9 (전체 fine-tune, 100%)                         69.07%     58.78%
  3      v8 (전처리 재설계: 300ms+퓨리티필터+envelope)      68.69%     56.92%
  4      v10-classifier_only (1.6% 파라미터 fine-tune)     68.36%     57.46%
  5      v6 (SubjectAware+Attention, 손실함수 수정)        67.79%     55.99%
  6      openclaw v7 (TCN+Attention+증강)                  67.56%     55.50%
  7      RandomForest v1                                   65.88%*    53.13%
  ...    (이하 v2.txt~v8.txt와 동일)

freeze_cnn이 수치상 1위이지만 v9와의 차이(+0.03p)는 사실상 측정 잡음 수준이라,
"freeze가 v9보다 낫다"고 결론 내릴 수는 없다. 이번 버전의 진짜 결론은 순위가
아니라: **"피험자별 fine-tuning에서 본 분산은 과적합 문제가 아니라 데이터(그
사람 고유의 신호 난이도) 문제다"**라는 것을 깨끗한 어블레이션으로 확인한
것이다. 이는 제안됐던 두 전략(freeze, Center/Focal Loss) 중 freeze 쪽의
전제("과적합 때문에 분산이 크다")가 틀렸다는 뜻이고, 향후 분산을 줄이려면
학습 전략을 바꾸는 것보다 "어려운 피험자의 데이터/신호 자체"를 들여다보는
방향이 더 가능성이 높다는 것을 시사한다.


[향후 개선 후보 (v10 시점까지 미착수)]

- Center Loss / 약하게 튜닝한 Focal Loss 시도 (애초에 같이 제안됐던 두 번째
  전략) — 다만 이번 결과로 "과적합 때문이 아니다"가 확인됐으므로, 이 손실
  함수들이 도움이 된다면 그 경로는 "과적합 억제"가 아니라 "클래스 경계를
  더 뚜렷하게 학습시키는" 다른 메커니즘을 통한 것일 가능성이 큼 — 기대치를
  거기에 맞춰서 설계해야 함.
- "어려운 피험자"(S28, S31 등)의 raw 신호를 직접 까서 비교 — 신호 진폭, SNR,
  채널별 노이즈 비율 등을 잘 되는 피험자(S01, S05, S40)와 비교해 공통점을 찾기.
- 피험자별로 다른 fine-tuning 강도(예: 어려운 피험자에게는 더 많은 augmentation
  이나 더 긴 학습)를 적용해보는 시도 — 모든 피험자에게 같은 레시피를 강제하는
  현재 방식 대신.
- 도메인 적응(DANN, MMD)으로 풀링 모델 자체의 일반화 성능 개선.
- E2(취약 그룹) 전용 추가 특징/아키텍처 보강 (v1 시점부터 계속 미착수 상태).
