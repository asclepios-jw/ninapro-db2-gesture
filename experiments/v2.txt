================================================================
v2 — "사람마다 신호 크기가 다르다": 피험자별 정규화 도입
================================================================

[이 버전을 시작한 계기]

v1 결과를 보고 사용자가 "성능이 안 좋다"고 지적했다. 원인을 분석한 결과, 가장 의심되는
지점은 정규화 방식이었다. v1은 40명 데이터를 모두 모은 뒤 "전체 기준"으로 한 번에
정규화(글로벌 정규화)했는데, 사람마다 전극 부착 위치, 피부 임피던스, 근육량, 지방층
두께 등이 달라서 같은 동작을 해도 EMG 신호의 절대적인 크기(진폭)가 사람마다 천차만별이다.
글로벌 정규화는 "40명 전체의 평균적인 크기"에 맞춰버리기 때문에, 신호가 원래 작은
사람과 큰 사람 사이의 차이를 모델이 동작 차이로 오인할 위험이 있다.


[해결책: 피험자별(per-subject) z-score 정규화]

code/data_utils.py의 normalize_per_subject() 함수를 새로 추가했다.
핵심 아이디어는 "각 사람 본인의 train 구간(rep1~4) 통계로만" 평균/표준편차를 구해서
그 사람의 신호를 정규화하는 것이다.

  mean = emg[train_mask].mean(...)   # train rep만 사용
  std  = emg[train_mask].std(...) + 1e-8
  normalized = (emg - mean) / std

왜 train rep만 쓰는가(매우 중요): val/test 구간의 통계까지 같이 써서 정규화하면,
모델이 학습 단계에서 "미래에 나올 val/test 데이터의 정보"를 미리 일부 알게 되는
데이터 누수(leakage)가 발생한다. 그래서 평균/표준편차는 반드시 train rep(1~4)만으로
계산하고, 그 통계를 val/test에도 그대로 적용한다.

이렇게 하면 "이 사람 안에서는 신호가 상대적으로 얼마나 큰가/작은가"라는 정보만 남고,
사람마다 다른 절대적인 신호 크기 차이는 제거된다. 이는 사람이 바뀌어도 통하는 모델을
만들겠다는 v1~v2 전체의 목표와도 일치하는 방향이다.


[버그 발견: E3 .mat 파일의 row 수 불일치 (이 버전 작업 중 튀어나온 사고)]

normalize_per_subject()를 추가하고 재실행하자 다음 에러가 발생했다:

  IndexError: boolean index did not match indexed array along axis 0
  (emg 5,238,693행 vs reps 5,238,692행)

원인을 파보니 피험자 1의 E3 파일(S1_E3_A1.mat)에서 emg 배열은 877,073행인데
restimulus/rerepetition 배열은 877,072행으로, 원본 데이터 자체에 1행이 어긋나 있었다
(다운로드된 원본 데이터의 결함으로 추정 — 우리가 만든 게 아니라 받은 데이터 자체의 문제).

조치: load_subject_raw()에서 각 exercise 파일을 로딩할 때마다
n = min(len(emg), len(labels), len(reps)) 로 세 배열을 공통 길이로 잘라내는
방어 코드를 추가했다. 수정 후 피험자 1을 재처리해 정상 동작을 확인했고,
윈도우 수도 26,192개로 수정 전과 거의 동일해 영향이 미미함을 확인했다.

(이 사고는 정규화 작업과는 별개의 독립적인 데이터 결함이었지만, 정규화 코드를
새로 추가하면서 처음으로 표면에 드러난 것이다 — 즉 "버그가 원래 있었는데 마침
이번에 건드린 코드 경로를 타면서 발견됐다"는 흔한 패턴.)

[학습 중 예상치 못하게 발생한 문제들 — 버전/환경/하드웨어]

위에서 다룬 E3 .mat 파일 row 불일치가 이번 버전에서 만난 유일한 "사고"였다.
이건 코드 버그나 환경 설정 문제가 아니라 원본 데이터 자체의 결함이었다는 점이
중요하다 — 즉 우리 환경(라이브러리 버전, 하드웨어)이 원인이 아니라 데이터를
새로운 방식(정규화)으로 건드리면서 우연히 드러난 잠재적 결함이었다.

하드웨어 자원 문제는 없었다 — 40명 전체를 다시 빌드하는 데도 RAM 125GB, 디스크
여유 공간 모두 충분했고 GPU 학습도 끝까지 안정적으로 돌았다. 배운 점은
"버그는 새 코드를 추가했을 때가 아니라, 새 코드가 기존에 안 건드리던 데이터
경로를 처음 통과할 때 드러난다"는 것이다 — 그래서 새로운 전처리 단계를 추가할
때마다 작은 단위(피험자 1명)로 먼저 검증하는 습관이 이후 버전들에서도 유지됐다.


[부수적으로 같이 처리한 문제: RandomForest 모델 용량]

v1에서 발견된 50.6GB rf_model.joblib 문제를 v2에서 함께 해결했다.
code/train_rf.py의 RandomForestClassifier에 max_depth=20 제한을 추가.
결과적으로 모델 용량이 13.5GB로 줄어듦(약 73% 감소).
다만 트리 깊이를 제한하면 각 트리가 표현할 수 있는 패턴의 복잡도가 줄어드는
트레이드오프가 있어, 정확도가 소폭 하락하는 부작용이 따라왔다(아래 결과 참고).

주의할 점: v2는 "피험자별 정규화"와 "RF max_depth=20 제한"이라는 두 가지 변경을
동시에 적용했기 때문에, RF 성능 변화가 둘 중 어느 것 때문인지 깔끔하게 분리하기는
어렵다. 이 점은 분석 결과 섹션에서 그대로 한계로 인정하고 기록했다.


[v2 결과]

| 모델          | Test Acc | Test Macro-F1 | 학습시간 |
|---------------|----------|----------------|----------|
| RandomForest (max_depth=20) | 61.08% | 50.34% | 313s |
| CNN1D                       | 60.97% | 41.57% | 1308s |
| CNN-LSTM                    | 64.14% | 48.48% | 3953s |


[v1 → v2 비교 — 모델별로 효과가 정반대로 나뉜 것이 핵심 발견]

| 모델          | Acc(v1) | Acc(v2) | ΔAcc    | F1(v1) | F1(v2) | ΔF1    |
|---------------|---------|---------|---------|--------|--------|--------|
| RandomForest  | 65.88%  | 61.08%  | -4.80p  | 53.13% | 50.34% | -2.79p |
| CNN1D         | 59.52%  | 60.97%  | +1.45p  | 38.95% | 41.57% | +2.63p |
| CNN-LSTM      | 63.56%  | 64.14%  | +0.59p  | 47.51% | 48.48% | +0.97p |

해석:
- 딥러닝 모델(CNN1D, CNN-LSTM)은 raw EMG 파형을 직접 입력으로 받기 때문에,
  피험자별 정규화로 사람 간 진폭 차이를 제거해준 효과가 곧바로, 그리고 일관되게
  성능 향상으로 이어졌다. 이는 "피험자별 정규화 자체는 옳은 방향"이라는 근거가 된다.
- RandomForest는 오히려 떨어졌다. 가능한 설명은: (1) RF가 쓰는 특징(MAV, RMS 등)은
  이미 어느 정도 신호의 "절대적 크기" 자체가 개인 식별/구분에 유용한 정보로 쓰이고
  있었을 수 있는데, 피험자별 정규화가 이 개인차 정보를 지워버렸을 가능성, (2) 동시에
  적용된 max_depth=20 제한 자체의 정확도 손실. 두 원인이 섞여 있어 단독 효과 분리는
  하지 못했고, 후속 분석 과제로 남겨두었다.
- 부가 효과: RF 모델 용량 50.6GB → 13.5GB (73% 감소), 디스크 문제 해소.


[이 시점에서의 전체 그림 — "82.7% vs 60%대" 오해 정리]

사용자가 기존 단일 피험자 결과(82.7%)와 신규 40명 풀링 결과(60%대)를 같은 기준으로
비교하며 성능이 나쁘다고 오인한 적이 있었다. 이는 풀고 있는 문제 자체가 다르기 때문이다
(v1.txt 서두 참고): 단일 피험자 모델은 그 사람 한 명에게 맞춰 최적화되는 "개인화 모델"이고,
40명 풀링 모델은 40가지 다른 생리적 특성을 동시에 일반화해야 하는 "범용 모델"이다.
sEMG 분야에서 subject-pooled 모델이 subject-dependent 단일 모델보다 정확도가 낮게
나오는 것은 잘 알려진 현상이며, 진짜 공정한 비교를 하려면 40명 각각 개별 모델을
학습해 평균을 내야 한다 (이 작업은 아직 미착수, 향후 과제로 기록).


[이 버전에서 다음 버전으로 넘어가게 된 이유 — 요약]

1. v1/v2 모두 여전히 40명 풀링 일반화의 본질적인 한계(60%대 정체)를 넘지 못했다.
2. 모델이 "이 신호가 누구의 것인지" 전혀 모른 채 학습한다는 점이 근본 원인으로 지목됐다
   → 피험자 ID 자체를 모델 입력으로 명시적으로 주어주는 아이디어(Subject-Aware
   Embedding)를 다음 단계(openclaw v3)에서 시도하게 됨.
3. 또한 rest 클래스가 test set의 43.2%를 차지하는 극심한 불균형 문제도 함께 지목되어,
   클래스 불균형 보정 기법(class weight, focal loss)을 같이 시도하게 됨
   — 이 시도가 v3~v5에서 큰 사고로 이어진다 (v3.txt 참고).
