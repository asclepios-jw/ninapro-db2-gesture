================================================================
v8 — "파라미터 튜닝의 한계 이후, 전처리를 다시 본다": 3단계 재설계
================================================================

[이 버전을 시작한 계기]

v6에서 67.79% / Macro-F1 55.99%로 최고 성능을 냈고, openclaw가 별도로 시도한
v7(TCN+Attention+증강)도 67.56%/55.50%로 v6를 넘지 못했다. 두 경로(아키텍처를
더 복잡하게, 손실 함수를 더 정교하게) 모두 막힌 상태에서, "지금 단계에서 파라미터
튜닝을 더 해도 70%대 초반이 한계"라는 판단이 나왔고, 전처리 쪽에 아직 시도하지
않은 개선 여지가 있는지를 다시 짚어봤다.

사용자가 제시한 시도 순서는 다음 세 가지였다:
  1) 윈도우/스텝 크기(현재 200ms/100ms 고정값) 비교 실험
  2) rectification/RMS envelope 채널 추가 — 지금 CNN은 raw bandpass 신호만 입력받음
  3) 윈도우 경계 레이블 다수결 처리 개선 — 동작 전환 구간 오염 가능성

이 순서를 그대로 따르기 전에 한 가지를 제안해서 조정했다: 1번(윈도우 크기)과
3번(경계 레이블)은 둘 다 "세그먼테이션 단계"를 건드리는 변경이라, 따로 떼어서
실험하면 어느 쪽 효과인지 구분하기 어렵다. 그래서 1번+3번을 한 세트로 같이
스윕하고, 2번(envelope 채널, 모델 입력 채널 수 자체가 바뀌어 가장 비용이 큰 변경)은
세그먼테이션 설정이 확정된 뒤 마지막에 얹는 순서로 바꿨다. 이 순서가 "싼 실험부터
끝내고 비싼 실험을 그 위에 얹는다"는 원칙에 맞다고 판단했다.


[1단계: 윈도우/스텝/라벨순도 스윕 — code/sweep_window_purity.py]

전체 40명으로 모든 조합을 다 학습시켜보면 시간이 너무 오래 걸리므로, 빠른 의사결정을
위해 8명 피험자 부분집합(S1, S6, S11, S16, S21, S26, S31, S36 — 5명씩 건너뛰며 골라
다양성 확보)과 RandomForest(특징 추출+학습이 몇 분 안에 끝나는 빠른 proxy 모델)로
6개 조합을 비교했다.

추가한 개념 — 라벨 순도(purity): 슬라이딩 윈도우 안에서 가장 많이 등장하는
레이블의 비율. 예를 들어 윈도우의 80%가 "동작 A", 20%가 "rest"라면 purity=0.8이다.
동작이 시작되거나 끝나는 경계에 걸친 윈도우는 이 값이 낮아진다. min_purity 임계값
미만인 윈도우를 통째로 버리면, 여러 레이블이 섞여 라벨이 모호한 "오염된" 샘플을
학습/평가에서 제외할 수 있다. (data_utils.segment_signal에 min_purity 파라미터로
구현, 기존 v1/v2 동작은 min_purity=0.0으로 그대로 보존됨.)

결과 (8명 부분집합, val accuracy / val macro-F1):

  윈도우/스텝       순도필터    val acc   val macro-F1
  300ms / 150ms     >=0.8       70.49%    62.30%   <- 최고
  300ms / 150ms     없음        69.20%    61.09%
  200ms / 100ms     >=0.8       68.27%    59.95%   (기존 윈도우 크기)
  200ms / 100ms     없음        67.54%    59.30%   (v1~v6 baseline과 동일 설정)
  150ms / 75ms      >=0.8       66.57%    57.93%
  150ms / 75ms      없음        65.90%    57.41%

패턴이 아주 명확했다: 윈도우가 길수록(150 -> 200 -> 300ms) 일관되게 좋아졌고,
어떤 윈도우 크기에서도 순도 필터(>=0.8)를 걸면 추가로 좋아졌다. 두 가설(긴
윈도우가 더 많은 시간적 컨텍스트를 준다, 경계 오염 제거가 라벨 노이즈를 줄인다)
모두 같은 방향으로 확인된 것이다. 300ms/150ms + purity>=0.8을 최종 설정으로
확정했다.


[2단계: 전체 40명 재구축 — code/build_dataset_v3.py]

확정된 설정으로 40명 전체를 다시 로딩/필터링/세그먼테이션했다.
결과: train 447,610 / val 108,323 / test 108,171 윈도우 (윈도우 길이 600 샘플 =
300ms), 50클래스, 19.1GB. (윈도우가 길어지고 스텝도 늘어난 데다 순도 필터로
일부가 제거되어, v2의 윈도우 수(약 102만개)보다 전체 윈도우 수는 줄었다.)


[3단계: rectification/RMS envelope 채널 추가 — code/data_utils.compute_envelope(),
 code/build_dataset_v8.py]

기존 CNN은 대역통과+노치 필터를 거친 raw EMG 12채널만 입력으로 받았다. 근전도
신호는 빠르게 진동하는 파형 자체보다 "진폭이 시간에 따라 어떻게 변하는가"
(움직임의 강도/타이밍)가 동작 구분에 중요한 정보를 담고 있는 경우가 많다. 이를
직접적으로 모델에 보여주기 위해 envelope(진폭 봉투) 채널을 추가했다.

계산 방법: raw EMG를 절댓값으로 정류(rectification)한 뒤, 10Hz 저역통과 필터를
걸어 빠른 진동은 지우고 느린 진폭 변화만 남긴다 (RMS와 비슷한 역할을 하는
"smoothed envelope"). 이 12채널 envelope을 기존 raw 12채널에 이어붙여 24채널을
만들고, 두 그룹 모두 피험자별 train-rep 통계로 z-score 정규화했다.

결과: train/val/test 윈도우 수는 2단계와 동일(같은 세그먼테이션 설정), 채널만
12->24로 늘어 38.3GB (data_processed/v8/).

모델은 v6의 SubjectAwareCNNLSTMAttention 아키텍처를 그대로 가져오고 입력 채널
수만 24로 맞췄다 (code/models_v8.py). 손실 함수, 체크포인트 선택 기준(val
macro-F1), epoch 수(30, patience 6) 등 학습 레시피는 v6와 완전히 동일하게
유지해서, "전처리 변경의 순효과"만 보이도록 설계했다 (code/train_cnn_v8.py).


[v8 결과]

  모델                                          Test Acc   Test Macro-F1   Weighted-F1   학습시간
  v8 (300ms+퓨리티필터+envelope, SubjectAware)   68.69%     56.92%          67.15%        ~4240s
  (비교) v6 (200ms, raw 12ch만)                  67.79%     55.99%          66.17%        4260s

[왜 개선폭이 작았는가 — 분석]

1단계 스윕에서는 8명 부분집합 기준으로 200ms->300ms+필터 전환이 val_macro_f1을
0.5930 -> 0.6230로, 약 +3.0p 끌어올렸다. 그런데 40명 전체 + envelope 채널까지
다 적용한 최종 결과는 v6 대비 +0.93p에 그쳤다. 부분집합에서 본 개선 효과가
전체 데이터로 확장됐을 때 절반 이하로 줄어든 것이다.

가능한 이유:
1. 부분집합(8명)에서의 RandomForest 비교와 전체(40명)에서의 딥러닝 비교는
   모델 자체가 다르다 — RF는 손으로 만든 시간/주파수 특징을 쓰고 딥러닝은
   raw 신호를 직접 학습한다. RF 입장에서는 윈도우가 길어지면 MAV/RMS 같은
   통계 특징이 더 안정적으로 추정되어 이득이 크지만, CNN+LSTM은 이미 자체적으로
   시간적 패턴을 학습할 수 있어서 같은 변화의 이득이 상대적으로 작았을 수 있다.
2. v6가 이미 이 데이터/태스크(40명 풀링, 50클래스, subject-aware 아키텍처)에서
   CNN+LSTM+Attention 계열이 낼 수 있는 성능에 상당히 근접해 있었을 가능성이
   있다 — v3~v5(구조 복잡화)에서도, v7(TCN+증강)에서도 비슷한 패턴이 나왔다는
   점과 같은 결을 가진 결과다.
3. envelope 채널이 추가한 정보가 raw 신호+CNN이 이미 학습 가능한 정보와 상당히
   중첩되었을 수 있다 — CNN의 초반 conv 레이어가 이미 일종의 정류/저역통과와
   비슷한 연산을 학습으로 근사할 수 있기 때문에, 명시적으로 envelope을 추가로
   넣어줘도 새로 얻는 정보량이 생각보다 적었을 수 있다.


[학습 중 예상치 못하게 발생한 문제들 — 버전/환경/하드웨어]

v8을 진행하면서 코드 버그나 환경 문제로 학습이 중단되거나 결과가 깨진 적은
없었다. 다만 작업 과정에서 실제로 마주친, 미리 예상하지 못했던 자잘한 이슈들은
다음과 같다:

1. 스윕 단계(8명 부분집합)에서 본 개선폭(+3.0p)이 전체 40명 + envelope까지 다
   적용한 최종 결과에서는 절반 이하(+0.93p)로 줄어들었다. 이건 버그가 아니라
   "작은 샘플로 빠르게 검증한 결과가 전체 규모로 그대로 확대되지는 않는다"는,
   미리 충분히 경계하지 못했던 일반적인 함정이었다. 8명 부분집합 + RandomForest
   조합은 "방향이 맞는지"를 빠르게 확인하는 데는 유효했지만, "효과의 크기"까지
   그대로 신뢰하면 안 된다는 걸 사후에 알게 됐다.
2. envelope 채널을 추가하면서 채널 수가 12->24로 늘었고, 그만큼 데이터셋
   용량도 19.1GB -> 38.3GB로 두 배 가까이 늘었다. 이번에는 로컬 컴퓨터의
   RAM(125GB)과 디스크(5TB 여유) 여력이 충분해 문제가 없었지만, 만약 envelope
   외에 추가 채널(예: 주파수 영역 특징)을 더 얹는 식으로 계속 확장한다면 다음
   버전에서는 메모리/디스크 여유를 미리 계산해봐야 한다는 걸 체감했다.
3. 윈도우 길이를 200ms(400 샘플)에서 300ms(600 샘플)로 늘리면서 한 윈도우당
   처리할 시퀀스가 길어졌는데도, 윈도우 개수 자체가 줄어든 덕분에(스텝도
   100ms->150ms로 늘림) 전체 학습 시간은 v6와 거의 같았다(약 4240s vs 4260s).
   "윈도우를 길게 하면 무조건 학습이 느려질 것"이라고 예상했었는데, 실제로는
   윈도우 개수 감소와 길이 증가가 거의 상쇄되어 시간 차이가 거의 없었던 것은
   예상과 달랐던 부분이다.

요약하면, v8 자체는 기술적으로 깨끗하게 돌아갔지만 "작은 규모 실험의 효과를
큰 규모로 그대로 확대 추정하면 안 된다"는 방법론적 교훈을 얻은 것이 가장 큰
수확이었다.

것"이 가장 큰 레버리지였고, 그 다음은 정규화/피험자 임베딩처럼 모델이 데이터를
해석하는 방식을 바꾸는 변경이었으며, 전처리 디테일(윈도우 크기, envelope)은
방향은 맞지만 한계 효용이 점점 작아지는 영역에 들어선 것으로 보인다.

단일 피험자 baseline(82.7%) 대비 격차는 v8 기준 약 14p 남아있다. 이 격차를
더 좁히려면 지금까지 시도한 "전처리/구조/손실함수" 축보다는, 풀링된 40명
모델이 안고 있는 근본적인 일반화 문제(사람마다 다른 EMG 패턴을 하나의
모델이 동시에 학습해야 하는 어려움)를 직접 다루는 접근 — 예를 들어 피험자별
fine-tuning이나 도메인 적응 — 이 더 큰 레버리지를 가질 가능성이 높다.


[향후 개선 후보 (v8 시점까지 미착수)]

- 40명 개별 모델 학습 후 평균 정확도로 단일 피험자 baseline(82.7%)과 동일 조건 비교.
- 라벨-EMG 시차(반응시간) 보정 — stimulus 시점과 실제 EMG onset 사이의 지연을
  라벨 시프트로 보정 (논의는 했으나 v8에서는 적용하지 않음).
