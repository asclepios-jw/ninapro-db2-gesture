[이 버전을 시작한 계기]

v28(64.69%) 이후에도 v10(69.10%) 대비 4.41p 갭이 남아 있었다.
data_utils.py 코드를 직접 읽어 v8 파이프라인의 실제 순서 확인:
  filter → |raw EMG| → lowpass env → stack 24ch → normalize(24ch, rep∉{5,6}) → window

v28은 12ch EMG만 먼저 정규화한 뒤 envelope을 계산했으나,
v29는 data_utils.py의 순서를 정확히 따름:
  - env를 raw filtered EMG에서 계산
  - 24ch 전체 jointly 정규화 (rep=0 포함, rep∉{5,6})
  - rep=0 윈도우 포함 (v8 segment_signal에 제외 로직 없음)

가설: v29 ≈ v8 전처리 → v10(69%) 근접 회복.


[방법: code/build_dataset_v29.py + code/train_cnn_v29.py]

파이프라인:
  filter(12ch) → |raw EMG| → lowpass env(12ch) → stack 24ch
  → normalize(24ch, 연속신호, rep∉{5,6} = rep0 포함) → window (rep=0 포함)

아키텍처: v25-v28과 동일 (Conv1d k=3 + ReLU + No MaxPool + BiLSTM)
데이터: 전처리전달_v29/ (build_dataset_v29.py 출력)

데이터 검증 (v8 실제 데이터와 비교):

  v29 train 447,500개  mean=0.0008  std=1.0837  EMG std=1.0664  Env std=1.1007
  → 거의 동일. 전처리 복제 성공 (윈도우 수 차이 -110개는 경미).

[기대와 실제가 어떻게 달랐는가 — 결정적 발견]

기대: v8 전처리 복제 → v8 pooled(68.68%) 근접.

실제: 63.57%. 데이터는 거의 동일한데도 5.11p 차이.

데이터 통계 비교로 전처리가 동일함을 확인한 상태에서 5.11p 차이가 남는다는 것은
→ 원인이 전처리가 아니라 아키텍처.

[핵심 발견: 아키텍처 비교]

  train_cnn_v8.py → models_v8.SubjectAwareCNNLSTMAttention
  train_cnn_v29.py → 인라인 SubjectAwareCNNLSTM

  v8 아키텍처 (models_v8.py):
    Conv1d(24→64, k=5, padding=2) + BN + ELU + MaxPool1d(2)
    Conv1d(64→128, k=3, padding=1) + BN + ELU + MaxPool1d(2)
    → 시퀀스 600 → 300 → 150으로 압축
    LSTM(128+32→128, 2L, bidir) ← Subject emb이 LSTM 입력에 연결 (매 타임스텝)
    Attention(tanh+linear, 비선형)
    Dropout(0.4) + Linear(256→50)

  v25-v29 아키텍처 (인라인):
    Conv1d(24→64, k=3) + BN + ReLU + (MaxPool 없음)
    Conv1d(64→128, k=3) + BN + ReLU + (MaxPool 없음)
    → 시퀀스 600 그대로 LSTM 입력
    LSTM(128→128, 2L, bidir) ← Subject emb 미포함
    Attention(linear softmax, 선형)
    Dropout(0.4) + Linear(256+32→50) ← Subject emb을 최종단에 연결

  차이: k5 vs k3, ELU vs ReLU, MaxPool 유무,
        Subject emb을 LSTM 입력 vs 출력에 연결, 비선형 vs 선형 Attention.


[전체 갭 재분석]

  전처리 갭 (동일 아키텍처 기준):
    v29(v8 전처리) vs v27(팀 10Hz): 63.57% vs 63.56% → +0.01p (전처리 동일화 시 거의 차이 없음)
    v28(norm→env) vs v27(env→norm): 64.69% vs 63.56% → +1.13p (정규화 순서의 효과)

  아키텍처 갭:
    v8(v8 arch + v8 data) vs v29(v25 arch + v8 data): 68.68% vs 63.57% → 5.11p

  결론:
    총 갭 6.52p (팀5Hz vs v10fine-tuned) 중:
      - 필터 차이:       +0.98p  (5Hz→10Hz)
      - 정규화 순서:    +1.13p  (env→norm→env)

      - 전처리 동일화: 차이 거의 없음 (v29≈v27)
