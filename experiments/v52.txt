================================================================
v52 — 온라인 시간 평활: 정직한(oracle 없는) 스트리밍 성능 회복
       인과적 74.7% / 중심 78.6% (프레임 73% → oracle 88%)
================================================================


[1] 계기
v51에서 프레임(73%)↔반복 다수결(88%) 15p 격차 = 시간적 착시 확인. 그러나 88%는
oracle 분할 전제. 이 버전은 '분할 정보 없이 인과적/온라인' 평활만으로 격차를
얼마나 회수하는지(정직한 배포 수치) 측정.


[2] 방법
앙상블 8모델 윈도우 확률을 피험자 내 시간순으로 두고:
  - 인과적(causal): 직전 W개 확률 평균 → argmax (실시간, 지연 0)
  - 중심(centered): ±W/2 확률 평균 → argmax (지연 ~W/2·150ms 허용)
피험자 경계만 존중, 제스처 경계는 '모름'(정직 조건). W 스윕. 추론 후처리, 재학습 0.


[3] 기대
경계/onset 윈도우의 일시적 rest-오분류가 평활로 상쇄 → 프레임 성능 상승.


[4] 결과
  기준 프레임(W=1): acc 73.00% / macroF1 0.6444 / hard 63.1%
  인과적 최고 (W=5, 900ms): acc 74.73% (+1.73p) / macroF1 0.6881 / hard 66.5%
  중심 최고 (W=19, 3000ms): acc 78.64% (+5.65p) / macroF1 0.7635 / hard 72.4%
  oracle 참조: 88.04%
  → 중심 평활이 프레임→oracle 격차의 38%를 분할 없이 회수.

  곡선 특성:
  - 인과적은 W=5~7에서 정점 후 하락(W=27 58%, W=39 47%). onset에서 직전 rest·
    이전 제스처를 끌고 와 과평활 시 급락. 실시간 순수 인과 평활의 한계.
  - 중심은 W=19(3s)까지 완만 상승 후 하락. 미래 컨텍스트로 경계 착시를 더 잘 상쇄.


[5] 문제
없음(추론 후처리). 평활은 피험자 내에서만, 제스처 경계 미사용(정직).


[6] 배운 점
- 시간 정보에 잠긴 15p 중 상당 부분은 '분할 없이도' 회수 가능(중심 +5.65p).
- 순수 인과(지연0)는 +1.7p로 제한 — 실시간 시스템의 현실적 한계.
- 약간의 지연(1~3s)을 허용하면 크게 개선(+5.65p) — 제스처 명령형 UI엔 수용 가능.
- 남은 격차(79→88%)는 '분할' 문제 → v53에서 실제 분할로 공략.
