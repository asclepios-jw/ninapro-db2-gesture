[기대와 실제가 어떻게 달랐는가]

기대: 30epoch를 완주한 피험자들이 더 많은 epoch에서 수렴하지 못했던 것이므로,
50epoch 시 전체적으로 1~2% 추가 개선 기대.

실제: 전체 +0.08p. Hard 피험자 +0.44p로 근소 개선됐지만 개별 변화량을 보면
오히려 퇴행한 피험자(Sub 2: -1.47p, Sub 3: -3.30p)가 일부 존재한다.

Sub 4는 30ep든 50ep든 정확히 58.83%로 고착 — 에포크와 무관한 한계임이 확실해졌다.


[원인 분석]

1. 에포크 증가는 수렴 속도 문제가 아닌 표현력 문제를 해결하지 못한다.
   피험자당 ~11,190 윈도우 / 50클래스 ≈ 224 윈도우/클래스. 데이터는 충분하다.
   문제는 현재 CNN+BiLSTM 아키텍처가 이 데이터에서 뽑을 수 있는 특징의 상한이
   ~69~70% 수준임을 의미한다.

2. Sub 3(best_ep=50, acc 하락)은 val macro-F1 기준 체크포인트가 test acc와
   다른 방향으로 개선됐음을 의미한다. 클래스 불균형 상황에서 F1 최적화가
   accuracy와 다른 방향을 가리킬 수 있는 사례.

3. Sub 2(best_ep=13)처럼 매우 일찍 수렴하는 피험자는 오히려 더 적은 epoch가
   적합하며, 50epoch는 불필요한 오버피팅 위험을 높인다.

4. LLM(MiniMax-M3) 외부 평가 결과와 일치: 현재 아키텍처 자체가 병목이며
   "multi-scale temporal feature 부재"와 "600 timestep LSTM 비효율"이 핵심 문제.


[v1~v22 전체를 관통하는 결론]

v21과 v22를 합쳐서 얻은 결론:
  - 개별 모델 = pooled 모델 (v21)
  - 에포크 증가 = 거의 무의미 (v22)
  - Hard 피험자 한계는 데이터 본연의 특성 + 아키텍처 표현력 부족

이제 "같은 아키텍처를 더 오래/다르게 학습"하는 방향은 소진됐다.
다음은 아키텍처 자체를 바꾸는 실험이 필요하다.

LLM 제안 + 문헌 기준으로 가장 유망한 변경:
  multi-scale dilated Conv (k=3/15/51, d=1/2/4)
  + MaxPool(stride=4) 다운샘플링 (600→150)
  + Transformer encoder (2L, d=128, 4head)
  → subject embedding(32) 유지


[향후 개선 후보]

- (신규, 최우선) v23: multi-scale conv + Transformer 아키텍처 (pooled 모델).
  LLM이 "단일 실험 최우선 후보"로 지목. 기대 효과: overall +2~4%, hard +4~8%.

- (이전부터) wavelet/scalogram frontend: conv 입력을 원시 신호 대신
  wavelet 계수로 교체. v23이 성공하면 v24로 시도.

- (이전부터) hard 피험자 채널별 SNR 진단: 불량 채널 마스킹으로
  신호 품질 자체를 올리는 방향.
