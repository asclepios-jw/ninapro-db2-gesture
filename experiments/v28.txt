[기대와 실제가 어떻게 달랐는가]

기대: 정규화→엔벨로프 순서가 v8과 같아졌으므로 큰 폭 개선 기대.

실제: +1.13p. 방향은 맞지만 여전히 4.41p 갭.

결론: **v28의 "정규화→env" 구현이 v8과 다른 방식이었다.**

사후 분석 (data_utils.py 확인):
  v8 실제 순서 (data_utils.py line 195-197):
    filter → |EMG|(raw) → lowpass → env(12ch) → stack 24ch → normalize(24ch 전체) → window

  v28에서 구현한 순서:
    filter → normalize(12ch EMG 연속) → |norm_EMG| → lowpass → env → stack 24ch

  → 두 가지 차이:
    1. 정규화 대상: v8은 EMG+envelope 24ch 전체를 jointly 정규화
                    v28은 EMG 12ch만 정규화, env는 항상 양수로 남음
    2. rep=0 처리: v8은 정규화 통계에 rep=0 구간 포함
                   v28은 train rep {1,2,3,4}만 사용 (rep=0 제외)
    3. 윈도우: v8은 rep=0 윈도우 포함 (segment_signal에 rep=0 제외 로직 없음)
               v27/v28은 rep=0 윈도우 명시적 제외
