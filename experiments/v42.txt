v42 — hard subject는 fine-tuning 제외 (BASE 고정): 70.36%
       v40과 사실상 동률 — 그러나 방법론적으로 잘못된 방향
================================================================


[1] 이 모델/설정을 선택한 계기 — 결정의 맥락

v40·v41 모두 hard 5명 {4,7,26,28,31}에서 fine-tuning이 반복적으로 역효과
(val 기준으로 FT가 선택됐으나 test에서 악화 = val≠test). hard는 검증 데이터가
적고 노이즈가 커 적응형 선택이 불안정.

가설: hard는 fine-tuning을 아예 빼고 pooled base로 고정하면 그 손실을 회수 →
     전체 소폭 상승 + 안정성.

※ 주의(사전 인지): 이 방안은 "실사용 시 이 사람이 hard인지 알아야 하는"
   런타임 의존성을 만든다. 미팅에서 지적된 실용성 우려와 정면으로 충돌 →
   채택 전 검증 목적의 실험으로 진행.


[2] 전 버전(v40)과 달라진 점

유일한 변경: 선택 규칙.
  v40: 40명 전원 adaptive (base vs fine-tuned 중 val_f1 높은 것)
  v42: hard 5명 → BASE 고정 (fine-tuning 아예 안 함)
       easy 35명 → 기존 adaptive

base·아키텍처·하이퍼파라미터는 v40과 100% 동일:
  BASE_CKPT = results/v40/best_model_v40.pth (v8 arch, 강한 증강 pooled 70.05%)
  freeze_cnn, Adam 1e-4, 15ep, focal γ2, batch 128.


[3] 변경 이유 + 기대했던 효과

hard의 val≠test 불안정을 피하는 가장 단순한 방법 = hard에게 개인화를 주지
않고 일반화(pooled base)만 쓰기. hard는 신호 품질 한계로 fine-tuning 이득이
불확실하므로, 안전하게 base 유지.

기대: 전체 +0.05~0.15p + 안정성 확보.


[4] 기대와 실제가 어떻게 달랐는가

기대: +0.05~0.15p
실제: **70.36%** (base 70.04% 대비 +0.32p, v40 70.35% 대비 **+0.01p**)
      → v40과 사실상 동률 (노이즈 수준).

  hard acc: 59.56%  (전원 BASE)  vs v40 59.36% → +0.20p
  easy acc: 71.90%  vs v40 71.92% → 거의 동일 (easy 재학습, stochastic)
  선택: hard 5명 BASE 고정 / easy 31명 FT, 4명 BASE

hard를 BASE로 고정한 효과 (v40 대비 피험자별):
    s04: 0.5721 → 0.5886  (+1.65p, 회수)
    s07: 0.6377 → 0.6414  (+0.37p, 회수)
    s31: 0.5462 → 0.5597  (+1.35p, 회수)
    s26: 0.6448 → 0.6275  (−1.73p, FT 이득 상실)
    s28: 0.5671 → 0.5608  (−0.63p, FT 이득 상실)
  → hard 순이득 +0.20p. 3명은 회수, 2명은 오히려 손해.
    즉 "hard 전원 BASE"는 s26·s28에겐 잘못된 처방. hard 내부도 이질적.

전체 평균에 미치는 영향: hard는 5/40 = 12.5%. hard +0.20p × 0.125 = +0.025p
→ 전체론 거의 무의미. easy 재학습 stochastic 변동에 묻힐 수준.


[5] 학습 중 예상치 못하게 발생한 문제들

기술적 문제: 없음. hard 5명은 fine-tuning 스킵으로 시간도 소폭 절약(27.4분).
base per-subject mean 70.04% = v40 재현 확인.


[6] 이번 버전에서 배운 점

**v42는 v40과 통계적으로 동률이며, 방법론적으로는 오히려 후퇴다.**

  성능: +0.01p (측정 노이즈). "신기록"이라 찍혔지만 무의미한 차이.
  방법론: "hard 전원 BASE" 규칙은 실사용 시 신규 사용자가 hard인지 판정해야
          하는 런타임 의존성을 만든다 → 미팅에서 지적된 실용성 우려를 악화.

**hard 내부도 이질적이라 "hard=일괄 base"는 옳지 않다.**
  s26·s28은 fine-tuning이 나았다. hard/easy 이진 라벨로 처리를 가르는 건
  거칠다. 올바른 건 라벨이 아니라 각자 데이터로 판단하는 것(= v40 adaptive).

**핵심 시사: hard/easy 라벨에 기반한 처리(v42)는 채택하지 않는다.**
  · 배포 가능한 답: pooled 단일 모델(70.05%, 개인 데이터·라벨 0)
  · 개인화가 필요하면: v40 adaptive (각 사용자 검증 데이터로 자동 결정,
    hard/easy 라벨 불필요) → +0.30p
  v42는 이 둘보다 실용성·해석에서 열등. 검증 실험으로서의 가치만 있음
  (= "hard-FT 불안정"과 "일괄 처리의 부적절함"을 데이터로 확인).


[7] 다음 버전에서 고쳐볼 점 + 기대 효과

v42로 "hard/easy 라벨 기반 처리" 경로 종료. 다음은 미팅 피드백과 일관되게
모두에게 동일하게 적용되는 레버로.

1. **(우선) 증강 강화 — 증강 강도 최적점 / 전극 shift**
   v40에서 강한 증강이 +0.80p(유일한 유효 base 레버). 최적점 추가 탐색 또는
   DB2 전완 둘레 전극 순환 shift 증강 추가. 전원 동일 적용, 배포와 무충돌.
   기대: +0.1~0.3p.

2. **(중기) 입력 표현 변경 — "용량"이 아닌 "정보"**
   backbone 확대(v41) 무효 확인 → 모델에 주는 정보를 바꾼다:
   시간-주파수(STFT/CWT) 또는 수공 특징(RMS/MAV/WL/ZC 등, DB2 검증됨).
   기대: 불확실하나 잠재력 +0.5p 이상.

3. **(보고) 프레이밍 정리**
   · 메인 숫자 = pooled 70.05% (전원 동일 학습)
   · fine-tuning = 옵션 개인 캘리브레이션 +0.30p (adaptive, 라벨 불필요)
   · hard/easy = 성능 분석용 진단 렌즈 (제품 기능 아님)
