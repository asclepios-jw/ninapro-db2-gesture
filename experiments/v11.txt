================================================================
v11 — Center Loss로 클래스 경계 보강 시도: 안전했지만 무효과
================================================================

[이 버전을 시작한 계기]

v10에서 "v9의 피험자별 분산은 과적합 때문이 아니라 데이터(피험자 신호) 쪽
근본 차이"라는 게 확인되면서, 같이 제안됐던 두 번째 전략(Center Loss/Focal
Loss로 클래스 경계를 더 뚜렷하게)을 시도할 차례가 됐다. v3~v5에서 FocalLoss
+ class weight 조합이 rest 클래스를 완전히 망가뜨린 전례가 있어서, 이번에는
그 사고와 무관한 메커니즘(Center Loss)을 먼저, 단독으로, 안전장치(매 epoch
rest recall 모니터링)를 달고 시도하기로 했다.


[Center Loss란 무엇이고 왜 시도했나 — code/models_v11.py]

Center Loss는 원래 얼굴 인식에서 나온 기법이다. 일반적인 분류 손실
(CrossEntropy)은 "정답 클래스의 확률을 높여라"만 신경 쓰는데, 이것만으로는
같은 클래스의 샘플들이 특징 공간에서 서로 멀리 떨어져 있어도 상관하지 않는다.
Center Loss는 클래스마다 학습 가능한 "중심점(center)"을 하나씩 두고, 같은
클래스의 샘플들이 그 중심점에 가까이 모이도록(intra-class compactness) 추가로
당겨준다.

이 프로젝트에 적용한 이유: confusion matrix를 v1부터 계속 봐온 결과, E2
그룹(움켜잡기형 동작들)처럼 서로 비슷한 제스처들이 자주 혼동되는 패턴이
반복됐다. 비슷한 제스처는 특징 공간에서도 서로 가깝게 뭉쳐 있을 가능성이
높은데, 같은 클래스를 더 강하게 뭉치게 하면 다른 클래스와의 경계가 상대적으로
더 뚜렷해질 것이라는 기대였다.

구현: SubjectAwareCNNLSTMAttention의 forward()가 분류기 직전의 attention
context 벡터(256차원)도 같이 반환하도록 확장하고, CenterLoss 모듈(클래스별
256차원 학습 가능 center, 50개)을 추가했다. 최종 손실 = CrossEntropy(label
smoothing 0.1) + 0.01 * CenterLoss. lambda=0.01로 작게 잡은 이유는 Center
Loss가 처음엔 값이 크게 나올 수 있어(랜덤 초기화된 center와 feature 간 거리),
주 손실(CE)을 압도하지 않게 하기 위함이었다.

v3~v5와의 핵심적인 차이: Center Loss는 "쉬운 샘플의 손실을 깎는" 메커니즘이
전혀 없다. rest 클래스가 쉽다고 해서 Center Loss가 더 작아지도록 설계된 게
아니라, 모든 클래스에 동일한 방식(자기 중심점에 가까워지기)으로 적용된다.
그래서 이론적으로는 v3~v5 같은 rest 붕괴가 일어날 메커니즘이 없다 — 이걸
직접 확인하기 위해 매 epoch마다 rest recall을 출력하도록 안전장치를 넣었다.

  #  깨끗하게 비교하기 위해 둘 다 동일한 초기화에서 새로 학습했다는 점이 중요)

[결과]

  모델                         Test Acc   Test Macro-F1   Rest Recall
  v8 (CE only)                 68.69%     56.92%           (정상, 별도 미기록)
  v11 (CE + CenterLoss 0.01)   68.64%     57.04%           91.47%

  학습 내내 rest recall은 90~98% 범위에서 건강하게 유지됐다 (1 epoch: 97.8%,
  28 epoch: 91.5% — 학습이 진행되며 천천히 낮아지긴 했지만 v3~v5의 0.0001~
  0.0002와는 전혀 다른 수준).


[기대와 실제가 어떻게 달랐는가]

기대: "비슷한 제스처들이 더 잘 분리되어 E2 그룹과 전체 macro-F1이 의미 있게
좋아질 것."

실제: 전체 결과는 v8과 거의 동일했다(-0.05p acc, +0.12p F1 — 측정 잡음 수준).
E2 그룹(클래스 18~40)만 따로 떼어 봐도 평균 F1 변화는 +0.005로 거의 없었고,
나머지 그룹도 -0.0016으로 거의 그대로였다. 즉 "안전하게 작동했지만 의도한
효과는 전혀 내지 못했다"는, v10과는 또 다른 종류의 결과다 — v10은 "가설
자체가 틀렸다"는 것을 보여줬고, v11은 "가설의 방향은 그럴듯했지만 이번
설정(lambda=0.01)으로는 효과가 측정되지 않았다"는 것을 보여준다. 이 둘의
차이는 중요하다: v11은 "이 방법이 안 된다"고 결론 내리기보다 "이 lambda
값에서는 효과가 없었다"로 남겨두는 것이 더 정확하다 — lambda를 더 키우면
다른 결과가 나올 수도 있다 (다만 그만큼 불안정해질 위험도 커진다).


[학습 중 예상치 못하게 발생한 문제들 — 버전/환경/하드웨어]

코드/환경 문제는 없었다. 다만 한 가지 설계 결정에 대한 불확실성이 남아있다:
lambda=0.01이라는 값은 "주 손실을 압도하지 않을 정도로 작게"라는 직관으로
고른 것이고, 실제로 학습 로그를 보면 Center loss 항(0.01 곱하기 전 raw 값)이
epoch 1의 6.54에서 epoch 28의 2.24까지 꾸준히 줄어들긴 했다 — 즉 center loss
자체는 의도대로 최적화되고 있었다. 문제는 이 항의 크기가 처음부터 끝까지
CE loss(2.18→1.14)에 비해 상대적으로 비중 있게 따라왔는데도, 분류 성능에는
거의 영향을 주지 못했다는 것이다. 이건 "더 큰 lambda를 안 써봐서 효과를
못 봤다"보다는 "이 lambda에서 center loss가 줄어드는 방향과 classification
accuracy가 좋아지는 방향이 서로 직접적인 인과관계가 약했다"는 해석에 더
가깝다 — 사전에 lambda를 여러 값으로 작게 스윕해보지 않고 한 값만 시도한
것이 이번 실험의 한계로 남는다.

v11은 풀링 모델(pooled base) 단계에서 시도한 변경 중 처음으로 "유의미한
변화가 전혀 없는" 결과다 — v6(+7.51p), v8(+0.93p)처럼 작더라도 방향이 있는
개선이 아니라, 정말로 플랫(flat)했다. 종합하면: 손실 함수를 "정상으로
되돌리는 것"(v6)은 큰 효과가 있었지만, 거기서 더 정교한 손실 함수 항을
추가하는 것(v11)은 이 시점에서는 추가 이득을 주지 못했다 — 즉 v6의 단순한
CE+label smoothing 자체가 이미 이 문제에 꽤 적합한 손실 함수였다는 정황
증거로 볼 수 있다.


[향후 개선 후보 (v11 시점까지 미착수)]

- Center Loss lambda 스윕 (0.001, 0.05, 0.1 등) — 이번엔 0.01 한 값만
  시도했으므로, 더 약하거나 더 강한 값에서 다른 결과가 나올 가능성은
  완전히 배제되지 않음. 다만 효과가 lambda에 매우 민감해야만 의미가 있다는
  점에서 우선순위는 낮춤.
- 약하게 튜닝한 Focal Loss(class weight 없이 gamma만 작게, 예: gamma=0.5)
  단독 시도 — v3~v5의 사고는 "class weight + focal loss 중첩"이 원인이었으므로,
  focal loss만 약하게 쓰는 것은 아직 검증되지 않은 경로.
- "어려운 피험자"(S28, S31 등) 신호의 공통 특징 분석 — v9/v10에서 계속
  미뤄지고 있는, 가장 근본적일 가능성이 높은 다음 단계.
- 도메인 적응(DANN, MMD)으로 풀링 모델 자체의 일반화 성능 개선.
- 40명 개별 모델 학습 후 평균 정확도로 baseline(82.7%)과 진짜 동일 조건 비교.
