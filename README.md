# Ninapro DB2 — 팔뚝 근전도로 50가지 손동작 분류

팔뚝 표면 근전도(sEMG) 12채널만으로 **50가지 손동작**을 분류합니다. 40명의 데이터를 **한 모델**에 모아, 사용 중에는 개인 라벨이나 매번의 재보정 없이 쓸 수 있는 범용 모델을 목표로 했습니다. (새 사용자는 처음 한 번 제스처 샘플로 등록하는 과정이 필요합니다. 근전 의수의 캘리브레이션과 같은 방식입니다.)

KBESA(큐베사) 바이오센서팀 프로젝트(2026-06 ~ 08)이고, 저는 Algorithm Leader를 맡았습니다. v1부터 v64까지 64번의 실험을 거쳤습니다.

**결론: 8모델 앙상블의 시험 정확도는 프레임 73.0%, 동작 단위 88.0%입니다.** 두 수치는 전제가 다릅니다. 프레임은 300ms 창 하나씩 채점한 값이고, 동작 단위는 제스처 경계를 안다고 가정하고 다수결한 값입니다. 시험 데이터의 피험자는 학습에도 등장한 사람들이므로, 처음 보는 사람에 대한 성능은 아닙니다.

> **이 레포의 범위**: v1~v64 전체 실험 코드(`code/`, 95개)와 버전별 실험 기록(`experiments/`), 최종 모델 문서입니다. 학습된 가중치(.pth), 전처리된 데이터, 결과 JSON은 용량 문제로 포함하지 않았습니다. 아래 수치는 모두 실험 기록에 남은 값이고, 이 레포만으로 바로 재계산할 수는 없습니다.

## 결과 (v64, 40명 통합 · 사용 중 개인 라벨 0)

| 평가 단위 | 정확도 | macro-F1 | 어려운 피험자 5명 |
|---|---|---|---|
| 프레임 (300ms 창 하나씩, 실시간) | **73.0%** (95% CI 70.8–75.3) | 0.644 | 63.1% (CI 59.1–67.1) |
| 온라인 평활 (1.5~3초 지연) | 78.6% | 0.764 | 72.4% |
| 실제 분할 (예측으로 경계 검출) | 80.4% | 0.781 | 73.4% |
| **동작 단위** (Ninapro 표준, 문헌 비교용) | **88.0%** (95% CI 86.4–89.6) | 0.846 | 83.9% (CI 77.0–89.5) |

- 신뢰구간은 피험자 40명을 복원추출한 부트스트랩(B=2000)으로 구했습니다. 어려운 피험자는 5명뿐이라 구간이 넓습니다.
- 재현 멤버를 바꾼 앙상블 6조합의 프레임 정확도는 72.75~72.83%(±0.03%p)입니다. 결과가 특정 seed에 크게 의존하지는 않았습니다.
- 팀 전처리 데이터 기준으로 62.6%(v25) → 73.0%(v48), **+10.4%p**입니다. 단 62.6%는 프로젝트 초기값이 아니라, 팀 전처리 데이터로 옮기면서 69.1%(v10)에서 떨어진 값입니다.
- S1 한 사람 전용 모델은 82.7%입니다. 다만 40명 각각의 전용 모델 평균은 69.00%로, 같은 시점의 통합 모델 68.69%와 거의 같았습니다(v21). 82.7%는 S1이 쉬운 피험자인 영향이 크고, 통합 자체의 손해는 작았습니다. 어려움의 중심은 사람마다 분류 난이도가 크게 다르다는 점입니다.

이 레포에는 그림 파일이 없습니다. 혼동행렬 이미지는 남아 있지 않아 넣지 않았고, 혼동 분석은 표와 실험 기록으로 대신합니다.

## 문제와 데이터

| 항목 | 내용 |
|---|---|
| 입력 | 팔뚝 12전극 sEMG(2 kHz) → 전처리 후 (24채널, 600샘플) = 300ms 창 + 피험자 ID |
| 출력 | 49개 손동작 + rest, 총 50클래스 |
| 데이터 | Ninapro DB2, 40명, 동작별 6회 반복 (E1~E3 합쳐 라벨 0~49) |
| 분할 | 반복 1~4 학습 / 반복 5 검증 / 반복 6 시험 (같은 40명이 모든 분할에 등장) |
| 규모 | 윈도우 학습 447,047 / 검증 108,303 / 시험 108,171 |
| 불균형 | rest가 윈도우의 약 44% |
| 어려운 피험자 | S4, S7, S26, S28, S31 (신호가 약하고 동작 간 차이가 작음, v12 진단) |

**평가 단위 두 가지.** 프레임은 윈도우마다 예측 하나를 채점합니다. 동작 단위는 시험 데이터를 (피험자, 라벨)이 연속되는 구간으로 묶어 구간마다 다수결합니다. 시험 윈도우 108,171개가 3,920개 구간으로 묶이며, 이 안에는 제스처 구간 1,960개와 rest 구간이 함께 들어 있습니다. 제스처만 계산한 macro-F1은 0.848입니다.

## 파이프라인

```
sEMG 12채널 (2 kHz)  →  대역통과 필터 + 포락선 (24채널)  →  300ms 창
   →  1D CNN 계열 모델 (멤버 구조 4종)  →  8모델 앙상블  →  (선택) 시간 후처리
```

### 전처리 (`code/build_dataset_v28.py`)

| 단계 | 설정 | 이유 |
|---|---|---|
| 대역통과 | 20~500 Hz, 4차 Butterworth | 드리프트와 고주파 잡음 제거 |
| 노치 | 50 Hz (Q=30) | 전원 간섭 제거 |
| 정규화 | 피험자별, 학습 반복의 연속 신호 통계 | 사람마다 다른 진폭 스케일 정렬 |
| 포락선 | 정규화된 EMG의 절댓값 → 10 Hz 4차 저역통과 | 빠른 파형에 느린 근육 활성 세기 추가 |
| 스택 | 원신호 12 + 포락선 12 = 24채널 | |
| 윈도우 | 300ms(600샘플), stride 150ms | 정확도와 지연의 절충 (v8 스윕) |
| 순도 필터 | 한 창에서 지배 라벨 비율 ≥ 0.8 | 경계 구간의 라벨 잡음 통제 |

### 모델

기반 구조는 `SubjectAwareCNNLSTMAttention`입니다.

```
입력 (B, 24, 600)
 → Conv1d 24→64 (k5) + BN + ELU + MaxPool    (B, 64, 300)
 → Conv1d 64→128 (k3) + BN + ELU + MaxPool   (B, 128, 150)
 → 피험자 임베딩(32차원)을 각 시점에 결합     (B, 150, 160)
 → BiLSTM 2층 (hidden 128)                    (B, 150, 256)
 → Attention 가중합                           (B, 256)
 → Dropout 0.4 + Linear                       (B, 50)
```

| 멤버 구조 | 변경점 | 파라미터 | 단일 pooled 정확도 |
|---|---|---|---|
| v8 | 기반형 | 805,266 | 70.05% (v40) |
| v44 | 시간영역 특징 60개 (RMS, MAV, WL, ZC, SSC × 12) 결합 | 816,778 | 70.20% |
| v45 | v44 + 주파수영역 특징 36개 (MNF, MDF, PKF × 12) | 819,154 | 70.31% |
| v41 | 잔차 CNN 백본 | 1,472,658 | 69.97% |

최종 모델 구조 사용 예:

```python
import torch
from model.final_model_cnn_lstm_attention import SubjectAwareCNNLSTMAttentionFeat

model = SubjectAwareCNNLSTMAttentionFeat()      # 24채널 입력, 50클래스, 피험자 40명
x = torch.randn(8, 24, 600)                     # (배치, 채널, 300ms @ 2kHz)
subject = torch.randint(1, 41, (8,))            # 피험자 번호 (임베딩 인덱스)
logits = model(x, subject)                      # (8, 50)
```

### 학습 (`code/train_cnn_v40.py` 기준)

| 항목 | 값 |
|---|---|
| 손실 | Focal Loss γ=2.0 (클래스 가중치와 겹쳐 쓰지 않음, v6 교훈) |
| 최적화 | AdamW lr=1e-3, weight decay=1e-4, CosineAnnealingLR |
| 학습량 | 50 epoch, 배치 256, early stopping patience 8 |
| 증강 | jitter σ0.06, magnitude warp σ0.30, time warp σ0.25, mixup α0.30 (각 p=0.5) |
| 체크포인트 선택 | 검증 macro-F1 최고 시점 |
| 환경 | RTX 2070 8GB, 멤버 하나당 약 2시간 |

v38 멤버만 v36 증강 설정으로 100 epoch 학습했습니다.

### 앙상블

각 멤버의 softmax 확률을 산술 평균합니다. 재학습은 없고 추론 비용만 멤버 수만큼 늘어납니다.

champion 앙상블 8개 중 3개가 위 사용 예의 구조(v44 seed 3개)이고, 나머지는 v45 2개, 기반 v8(v40, v38) 2개, 잔차 CNN(v41) 1개입니다. 배포 구성은 정확도 우선 `champ8`(8모델)과 강건성 우선 `robust3`(3모델, 의수 실사용 가정) 두 가지입니다. 세부 파라미터는 [`docs/final_model_spec_v64.txt`](docs/final_model_spec_v64.txt)에 있습니다.

## 결과 상세

### 배포 구성

| 구성 | 멤버 | 프레임 | 동작 단위 | 어려운 5명(프레임) | 추론 비용 |
|---|---|---|---|---|---|
| single | v45 | 70.3% | 85.9% | 60.0% | 1× |
| robust3 | v61 + v62 + v63 (채널 드롭아웃) | 72.0% | 86.8% | 62.0% | 3× |
| 다양 5 | v44 + v45 + v40 + v41 + v38 | 72.75% | 87.9% | 63.0% | 5× |
| champ8 | 8모델 | 73.0% | 88.0% | 63.1% | 8× |

멤버 수를 늘릴 때의 프레임 정확도(모든 조합 평균)는 N=1 70.09%, N=2 71.65%, N=4 72.51%, N=8 73.00%입니다. 이득은 뒤로 갈수록 줄어듭니다. 같은 크기의 조합끼리 차이는 ±0.2%p 안팎입니다.

### 강건성 (프레임 정확도, 시험 데이터 일부 또는 전체에 교란 적용)

| 조건 | champ8 | robust3 |
|---|---|---|
| 정상 | 73.0% | 72.0% |
| 전극 1개 고장 | 59.6% | 70.7% |
| 전극 2개 고장 | 52.6% | 68.4% |
| 전극 3개 고장 | 48.5% | 65.8% |

robust3은 학습 중 각 전극을 확률 0.10으로 끄는 채널 드롭아웃을 넣은 모델입니다. 같은 구조에 드롭아웃이 없는 3모델(orig3)은 champ8처럼 무너졌습니다(전극 1개 고장 58.96%). 전극 고장을 흉내 낸 것일 뿐, 실제 전극이 떨어진 신호로 측정한 값은 아닙니다.

잡음에는 강했습니다(σ=0.2에서 −0.48%p). 급격한 게인 변화에는 약합니다(0.5배 −19.7%p, 2배 −23.0%p). 이 게인 시험은 정규화 후 값을 바꾼 최악의 경우이고, robust3에도 게인 대응은 넣지 않았습니다.

## 무엇이 성능을 움직였나

| 결정 | 이득 | 근거 |
|---|---|---|
| 버그 수정 (손실 보정이 겹쳐 "쉬운 동작을 무시"하던 문제) | macro-F1 +7.5%p, 정확도 +3.65%p | v2 → v6 |
| 올바른 아키텍처 (초기 급락의 원인은 전처리가 아니라 아키텍처) | +4.7%p | v27 → v30 |
| 앙상블 (서로 다른 seed·구조 8개 모델의 확률 평균) | +2.7%p | v45 pooled → v48 |
| 정규화 후 포락선 계산 | +1.13%p (v8 구조에서는 +0.45%p) | v27 → v28, v30 → v32 |
| 포락선 저역통과 5 Hz·2차 → 10 Hz·4차 | +1.0%p | v25 → v27 |
| 라벨을 보존하는 데이터 증강 | +0.8%p | v36 → v40 pooled |

몇 개의 큰 결정이 대부분을 만들었고, 세밀한 튜닝은 0.1%p 단위였습니다. 0.1%p 수준의 이득은 노이즈일 수 있습니다.

| v25~v30 | 팀 전처리 데이터로 이전 | 62.58%로 하락 후 68.25%로 회복 | 전처리를 먼저 의심했지만 차이의 약 72%가 아키텍처 |

| v38~v39 | 100 epoch 장기 학습 | 69.48%, 미세조정과 합쳐도 69.65% | 단독으로는 이득이 작음 |
| v41 | 잔차 CNN (파라미터 1.8배) | pooled −0.08%p | 용량은 병목이 아니었음. 단 앙상블 멤버로는 도움 |
| v42 | 어려운 피험자를 미세조정에서 제외 | 70.36% (사실상 동률) | 배포 때 라벨이 필요해져 채택 안 함 |
| v43 | 전극 shift 증강 | −1.56%p | 전극 아래 근육이 달라져 라벨 의미가 깨짐 |
| v49~v50 | macro-F1 재균형 (로짓 보정, 샘플러) | 보정 안 함이 최선. 샘플러는 64.35% / 0.568 | 원인이 불균형이 아니었음 |
| v54 | 스펙트로그램 2D-CNN 멤버 | 단독 57.13%, 앙상블 이득 0 | 앙상블 멤버에도 강도 하한이 있음 |
| v55 | 학습 시간 보정 | 프레임 −1.1~−4.8%p, 동작 단위 82.6% | 오프라인·동작 단위 전용으로만 의미 |
| v56 | 자기지도 대조학습 | 뚜렷한 이득이 보이지 않아 중단 | 기록은 v57 끝에 짧게 남김, 미채택 |

v49까지는 낮은 macro-F1(0.64)을 신호의 한계로 해석했습니다. 외부 LLM(MiniMax) 검토에서 그 결론이 성급하다는 지적을 받고 v51에서 동작 단위로 다시 계산해 해석을 바꿨습니다. v3~v5와 v7은 기록상 별도 에이전트 트랙(openclaw)으로 진행한 실험입니다.

## 배운 것

1. **평가 단위가 결론을 바꿉니다.** 프레임 단위 73%, 낮은 macro-F1(0.64)은 "신호의 한계"처럼 보였지만, 주된 오류는 동작 경계나 약한 구간에서 순간적으로 rest로 놓치는 것이었습니다. 경계를 아는 동작 단위로 보면 88%, macro-F1 0.85입니다. 그만큼 실시간 프레임 성능이 높아졌다는 뜻은 아닙니다.
2. **용량이 아니라 정보와 다양성입니다.** 파라미터를 1.8배로 늘려도 이득이 없었습니다. 반면 단독으로는 실패한 모델도 앙상블 멤버로는 도움이 됐습니다.
3. **증강은 라벨의 의미를 보존해야 합니다.** 전극 위치를 돌리는 증강은 DB2의 근육 배치와 맞지 않아 −1.6%p였습니다.
4. **강건성은 따로 챙겨야 합니다.** 전극 하나가 고장 나면 −13.5%p였는데, 채널 드롭아웃 증강을 넣은 robust3 모델은 같은 상황에서 70.7%를 유지했습니다(정상 조건에서는 −1.0%p).
5. **외부 검토가 자기 사각지대를 잡습니다.** 다른 모델의 검토로 평가 단위 문제를 발견해, 프레임 73.0%와 동작 단위 88.0%를 구분해 보고하게 됐습니다.

## 한계

- **처음 보는 사람에 대한 성능이 아닙니다.** 시험 데이터는 학습에 쓴 40명의 다른 반복입니다. 피험자 임베딩을 쓰므로 새 사용자는 등록이 필요합니다. 등록 절차는 문서상 설계이고, 새 피험자로 검증하지 않았습니다.
- **동작 단위 88.0%는 경계를 안다는 전제의 값입니다.** rest 구간도 평가에 포함됩니다. 경계를 예측으로 찾으면 80.4%이고, 지연 없는 프레임은 73.0%입니다.
- **일부 선택은 시험 데이터를 보고 했습니다.** 멤버 학습과 체크포인트 선택은 검증 데이터로 했지만, 앙상블 조합(v47~v48)과 평활 창·분할 파라미터(v52~v53)는 시험 데이터에서 스윕해 골랐습니다. 9개 후보 전부를 쓰면 72.98%, 조합 간 차이도 ±0.2%p 안팎이라 영향은 작아 보이지만, 수치가 약간 낙관적일 수 있습니다.
- **시험 반복이 하나입니다.** 반복 6 한 번으로 평가했고, 반복을 바꾼 교차검증은 하지 않았습니다.
- **단일 데이터셋입니다.** 다른 데이터셋, 실제 사용자, 실시간 폐루프에서는 검증하지 않았습니다.
- **추론 비용이 큽니다.** 앙상블은 멤버 수만큼 계산이 늘어나고, 임베디드 환경에서 측정하지는 않았습니다.
- **어려운 피험자 수치는 표본이 5명입니다.** 동작 단위 기준 CI가 77.0~89.5%로 넓습니다. hard/easy 구분 자체가 결과를 보고 정한 것이라 순환성 지적도 있었습니다.

## 재현 방법

전체 재현에는 Ninapro DB2 원본과 GPU가 필요합니다. 코드의 데이터·결과 경로는 학습에 쓴 서버 기준(`/mnt/data/medical_project/...`)으로 적혀 있어, 각 스크립트 상단의 `DATA_DIR`, `OUT_DIR` 등을 바꿔야 합니다.

```bash
# 1) 환경 (Python 3.13, PyTorch 2.12 + CUDA 13.0)
docker build -t ninapro-dev docs/

# 2) 전처리: 24채널 300ms 창 생성
python code/build_dataset_v28.py --data_dir <DB2 폴더> --out_dir <출력 폴더>

# 3) champion 멤버 학습 (모델당 약 2시간)
python code/train_cnn_v40.py
python code/train_cnn_v38.py
python code/train_cnn_v41.py
python code/train_cnn_v44.py
V44_RUN=_rep1 V44_SEED=101 python code/train_cnn_v44.py
V44_RUN=_rep2 V44_SEED=202 python code/train_cnn_v44.py
python code/train_cnn_v45.py
V45_RUN=_rep2 V45_SEED=222 python code/train_cnn_v45.py

# 4) 통계·배포·추론·강건성 (재학습 없음)
python code/stability_v57.py
python code/deploy_v58.py
python code/inference_v59.py
python code/robustness_v60.py

# 5) robust3
python code/train_cnn_v61.py
CHDROP_MODEL=v44 CHDROP_OUT=results/v62 python code/train_cnn_chdrop.py
CHDROP_MODEL=v45 CHDROP_OUT=results/v63 python code/train_cnn_chdrop.py
python code/robust_ensemble_v64.py
```

- 일부 멤버(v44, v45, v40, v41, v38 원본)는 seed를 고정하지 않고 학습했습니다. 그래서 다시 학습하면 수치가 조금 달라질 수 있습니다. "결정론적 재현"(v59)은 저장된 체크포인트로 추론했을 때의 이야기입니다.
- 위 사용 예 코드는 CPU에서 실행해 출력 크기 `(8, 50)`, 파라미터 816,778개를 확인했습니다.
- 자세한 절차는 [`docs/final_model_spec_v64.txt`](docs/final_model_spec_v64.txt) 15절(재현 절차)에 있습니다.
- 필요 패키지: `docs/requirements.txt` + PyTorch (Dockerfile 참고)
- `code/ask_minimax.py`, `code/evaluate_with_llm.py`는 외부 LLM 검토용 스크립트이고, API 키는 환경변수(`NVIDIA_API_KEY`)에서 읽습니다.
