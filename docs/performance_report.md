# Ninapro DB2 Gesture Classification — 성적표 & 성능 평가

데이터: Ninapro DB2, 40명 피험자 × E1+E2+E3 (50 클래스: rest + 49 제스처), 12채널 sEMG, 2kHz.
전처리: 대역통과(20–500Hz) + 노치(50Hz) 필터 → 200ms 윈도우/100ms 스텝 슬라이딩 세그먼테이션.
분할: subject-dependent, repetition 기준 (train: rep1-4, val: rep5, test: rep6), 40명 풀링.
Test set: 169,281개 윈도우 (rest 비중 43.2%, 클래스 불균형 심함 → **accuracy보다 macro-F1이 더 정직한 지표**).

---

## 1. 참고 baseline — 기존 단일 피험자 프로토타입

`notebooks/ninapro_db2_pipeline_claude.ipynb` (이번 작업 이전에 존재, 수정하지 않음)

| 항목 | 값 |
|---|---|
| 대상 | 피험자 1명(S1)만 |
| 클래스 구성 | 동일 (E1+E2+E3, 50 클래스) |
| 모델 | CNN1D |
| Test accuracy | **82.7%** |

이 결과는 **40명 풀링 모델과 직접 비교 불가**. 단일 피험자는 그 사람의 전극 위치·근육량·피부 임피던스에 모델이 맞춰질 수 있어 훨씬 쉬운 문제. 40명 풀링은 모델이 서로 다른 40가지 생리적 특성을 동시에 일반화해야 하므로 정확도가 떨어지는 것이 자연스러운 결과.

## 2. v1 — 모델별 성적표 (글로벌 정규화)

| Model | Test Acc | Test Macro-F1 | Weighted-F1 | 학습시간 |
|---|---|---|---|---|
| RandomForest (n=300, max_depth=None) | 65.88% | 53.13% | 62% | 268s |
| CNN1D | 59.52% | 38.95% | 55% | 1217s |
| CNN-LSTM | 63.56% | 47.51% | 61% | 3629s |

**클래스 패턴**: 세 모델 공통으로 E2(움켜잡기형 기능적 동작) 그룹이 가장 약함, E3(힘 측정 관련 동작) 그룹이 가장 강함.
**알려진 이슈**: RandomForest 모델 파일(`rf_model.joblib`)이 **50.6GB** — `max_depth` 제한 없이 700K 샘플로 트리가 과도하게 자람.

## 3. v2 — 모델별 성적표 (피험자별 정규화 + RF max_depth=20)

| Model | Test Acc | Test Macro-F1 | Weighted-F1 | 학습시간 |
|---|---|---|---|---|
| RandomForest (n=300, max_depth=20) | 61.08% | 50.34% | — | 313s |
| CNN1D | 60.97% | 41.57% | — | 1308s |
| CNN-LSTM | 64.14% | 48.48% | — | 3953s |

**변경 사항**: (1) 각 피험자 본인의 train-rep 통계로 z-score 정규화 (피험자 간 신호 진폭 차이 제거), (2) RandomForest `max_depth=20` 제한 (모델 용량 문제 해결).

## 4. v1 → v2 비교 (모델별 업그레이드 효과)

| Model | Acc (v1) | Acc (v2) | ΔAcc | F1 (v1) | F1 (v2) | ΔF1 |
|---|---|---|---|---|---|---|
| RandomForest | 65.88% | 61.08% | **-4.80p** | 53.13% | 50.34% | -2.79p |
| CNN1D | 59.52% | 60.97% | **+1.45p** | 38.95% | 41.57% | +2.63p |
| CNN-LSTM | 63.56% | 64.14% | **+0.59p** | 47.51% | 48.48% | +0.97p |

**해석**:
- **딥러닝 모델(CNN1D, CNN-LSTM)**: 피험자별 정규화로 일관되게 개선. raw EMG를 직접 입력받기 때문에 피험자 간 진폭 차이 제거가 직접적으로 도움이 됨.
- **RandomForest**: 오히려 하락. 두 변경(정규화 + max_depth 제한)이 동시에 적용되어 순효과 분리는 어려우나, 시간/주파수 도메인 특징(MAV, RMS 등)이 피험자별 정규화로 개인차 정보를 잃었을 가능성 + max_depth 제한 자체의 정확도 손실이 합쳐진 결과로 추정.
- **부가 효과**: RF 모델 용량 50.6GB → 13.5GB (73% 감소), 디스크 문제 해결.

## 5. openclaw v3~v5 — 별도 지시로 진행된 추가 실험 (실패, 원인 분석)

사용자가 `openclaw`에 별도로 지시한 작업. v2의 한계(40명 풀링 일반화, rest 43% 불균형)를 해결하기 위해 **피험자 ID 임베딩**(`nn.Embedding`)을 CNN-LSTM에 추가하고, attention pooling(v4), ResNet1D 백본(v5)으로 아키텍처를 발전시킴. 단, 클래스 불균형 보정으로 **FocalLoss(gamma=2.0) + inverse-frequency class weight**를 도입하고 체크포인트는 **val_loss 최저** 기준으로 선택.

| Model | Test Acc | Test Macro-F1 | rest(0) recall |
|---|---|---|---|
| v3 (SubjectAware CNN-LSTM) | 30.78% | 40.29% | 0.0001 |
| v4 (+Attention) | 32.36% | 42.34% | 0.0002 |
| v5 (+ResNet1D 백본) | 33.13% | 43.21% | 0.0002 |

**버그 원인**: rest class 비중이 워낙 커서(43%) inverse-frequency 가중치가 rest에 극단적으로 작은 값을 부여했고, FocalLoss의 `(1-pt)^gamma` 항이 이미 잘 맞히는(=쉬운) rest 샘플의 손실을 한 번 더 깎아버려 두 메커니즘이 같은 방향으로 중첩 적용됨. 그 결과 모델이 rest를 거의 예측하지 않는 쪽으로 학습됨(recall 0.0001~0.0002). rest가 테스트셋의 43%이므로 accuracy가 64%→31~33%로 붕괴. 체크포인트를 **val_loss**로 고른 것도 이 왜곡된 손실 지형에서 "좋아 보이는" 잘못된 지점을 고르게 만든 부차적 원인.
아키텍처 개선(임베딩, attention, ResNet) 자체는 타당한 시도였으나, 손실 함수 버그에 가려져 v3~v5 어디서도 정상 효과를 확인할 수 없었음.

---

## 6. v6 — 버그 수정 버전 (openclaw 아키텍처 + 정상 손실 함수)

`openclaw/models_v6.py`, `openclaw/train_cnn_v6.py`. v4의 아키텍처(SubjectAware Embedding + Attention pooling)는 그대로 유지하고, 다음만 수정:

1. `FocalLoss + inverse-frequency weight` → `CrossEntropyLoss(label_smoothing=0.1)` (v1/v2에서 이미 검증된 손실 함수)
2. 체크포인트 선택 기준: `val_loss` → **val macro-F1**
3. Epoch 수 30 + early stopping(patience=6)으로 v1/v2와 동일한 학습 강도로 통일 (공정 비교)

| Model | Test Acc | Test Macro-F1 | Test Weighted-F1 | 학습시간 |
|---|---|---|---|---|
| **v6 (SubjectAware+Attention, fixed)** | **67.79%** | **55.99%** | 66.17% | 4260s |

**v2 대비**: Acc +3.65p, Macro-F1 +7.51p — 지금까지 만든 모든 모델(v1, v2, v3~v5) 중 최고 성능. 피험자 ID 임베딩이라는 아이디어 자체는 유효했고, 손실 함수 버그만 걷어내자 바로 효과가 드러남.

## 7. v8 — 전처리 재설계 (윈도우/스텝 스윕 + 라벨 순도 필터 + envelope 채널)

v6가 한계(67.79%)에 도달한 후, 파라미터 튜닝보다 **전처리**에 더 개선 여지가 있다는 판단으로 3단계로 진행:

**1단계 — 윈도우/스텝/라벨순도 스윕** (`code/sweep_window_purity.py`, 8명 부분집합 + RandomForest proxy로 빠르게 비교)

| Window/Step | Purity 필터 | Val Acc | Val Macro-F1 |
|---|---|---|---|
| **300ms/150ms** | **≥0.8** | **70.49%** | **62.30%** |
| 300ms/150ms | 없음 | 69.20% | 61.09% |
| 200ms/100ms (기존) | ≥0.8 | 68.27% | 59.95% |
| 200ms/100ms (기존, 필터 없음) | 없음 | 67.54% | 59.30% |
| 150ms/75ms | ≥0.8 | 66.57% | 57.93% |
| 150ms/75ms | 없음 | 65.90% | 57.41% |

결론: 윈도우가 길수록(300ms), 그리고 라벨 순도 필터(윈도우 내 최빈 라벨 비율 ≥0.8, 동작 전환 경계의 오염된 윈도우 제거)를 걸수록 일관되게 좋아짐 → **300ms/150ms + purity≥0.8**로 확정.

**2단계 — 전체 40명 재구축**: `code/build_dataset_v3.py` → `data_processed/v3/` (윈도우 600 샘플, train 447,610 / val 108,323 / test 108,171, 19.1GB).

**3단계 — rectification/RMS envelope 채널 추가**: `code/data_utils.compute_envelope()`로 원신호를 정류(절댓값)+저역통과(10Hz)한 envelope 12채널을 raw 필터링 신호 12채널에 이어붙여 24채널로 확장 (`code/build_dataset_v8.py` → `data_processed/v8/`, 38.3GB). 모델은 v6와 동일한 SubjectAware+Attention 아키텍처를 채널 수만 24로 맞춰 재사용 (`code/models_v8.py`, `code/train_cnn_v8.py`).

| Model | Test Acc | Test Macro-F1 | Test Weighted-F1 | 학습시간 |
|---|---|---|---|---|
| **v8 (300ms+purity필터+envelope, SubjectAware+Attention)** | **68.69%** | **56.92%** | 67.15% | ~4240s |

**v6 대비**: Acc +0.90p, Macro-F1 +0.93p — 개선 방향은 맞았지만 v2→v6 때(+3.65p/+7.51p)에 비하면 효과는 작음. 즉 전처리 쪽에 여지가 있다는 판단은 맞았으나, 이미 v6 시점에 모델이 이 데이터/태스크 조합에서 낼 수 있는 성능에 상당히 근접해 있었던 것으로 보임 (openclaw `flow/v7.txt`의 결론과도 일치 — "구조를 더 복잡하게/입력을 더 풍부하게 만든다고 항상 크게 좋아지는 건 아니다").

## 8. v9 — 라벨-EMG 시차 보정 + 피험자별 Fine-tuning

v8 이후 "파라미터 튜닝은 한계, 전처리도 효과가 줄어드는 중"이라는 판단 하에, 단일 피험자 baseline(82.7%)과의 격차(약 14p)를 메우기 위한 더 근본적인 접근 두 가지를 시도:

**시도 1 — 라벨-EMG 시차 보정** (`code/data_utils.apply_label_delay()`, `code/sweep_delay.py`): NinaPro restimulus 라벨과 실제 EMG 반응 사이의 인간 반응시간(100~300ms) 지연을 보정하는 가설. 8명 부분집합 + RandomForest로 delay_ms ∈ {0,50,100,150,200,250} 스윕.

| delay_ms | Val Acc | Val Macro-F1 |
|---|---|---|
| **0 (보정 없음)** | **70.49%** | **62.30%** |
| 50 | 70.21% | 61.99% |
| 100 | 70.06% | 61.94% |
| 150 | 70.12% | 62.17% |
| 200 | 69.78% | 61.68% |
| 250 | 69.40% | 61.55% |

**결과: 가설 반증.** delay=0(보정 없음)이 가장 좋고, 지연을 추가할수록 일관되게 나빠짐. restimulus는 NinaPro 측에서 이미 실제 동작 타이밍에 맞춰 보정된 라벨이라, 추가 보정이 오히려 역효과를 낸 것으로 추정. **이 방향은 더 이상 시도하지 않음.**

**시도 2 — 피험자별 Fine-tuning** (`code/finetune_v9.py`): v8 pooled 체크포인트를 시작점으로, 40명 각각 본인의 train 데이터(~11,000 윈도우)로 최대 15 epoch(lr=1e-4) 추가 학습 후 본인 test로 평가.

| 구분 | 평균 Test Acc | 평균 Test Macro-F1 |
|---|---|---|
| Pooled (v8 base) | 68.68% | 57.84% |
| **Fine-tuned (v9)** | **69.07%** | **58.78%** |
| 차이 | +0.39p | +0.94p |

평균 개선은 작지만(+0.39p), **피험자 간 분산(std_acc 7.56%p)이 평균 개선폭보다 훨씬 큼** — 일부(S33 +1.31p, S25 +1.04p)는 의미 있게 좋아지고 일부(S22 -1.16p, S34 -0.75p)는 오히려 나빠짐. 더 중요한 발견: fine-tuning 여부와 무관하게 일부 피험자(S01 83%, S05 85%, S40 83%)는 **풀링 모델만으로도 이미 단일 피험자 baseline(82.7%)에 도달**해 있었고, 반대로 일부(S28 54%, S31 56%)는 fine-tuning을 해도 baseline에 한참 못 미침 (`results/v9/per_subject_comparison.png` 참고). 즉 "40명 평균 68.69%"는 서로 다른 두 그룹(풀링에 잘 맞는 사람 / 안 맞는 사람)이 섞인 평균이라는 게 처음으로 명확히 드러남.

## 9. v10 — Freeze 강도 어블레이션 (과적합 가설 검증)

v9의 분산(std_acc 7.56%p)이 평균 개선폭(+0.39p)보다 큰 것을 보고, "피험자당 데이터가 적은데(11,000개) 전체 네트워크를 다 풀어서 fine-tuning하면 과적합으로 분산이 커진다"는 가설이 제기됨. CNN 백본을 얼리고 classifier/attention만 학습하면 더 안정적일 것이라는 예상으로 어블레이션 진행 (`code/finetune_v10.py`). v9와 동일 설정(epoch/lr/데이터)에서 학습 가능한 파라미터 비율만 바꿔 비교:

| 방식 | 평균 Acc | 평균 Macro-F1 | std(Acc) | 학습시간 |
|---|---|---|---|---|
| Pooled (v8, fine-tune 없음) | 68.68% | 57.84% | — | — |
| classifier_only (1.6% 파라미터만 학습) | 68.36% | 57.46% | 7.60%p | 885s |
| **freeze_cnn (96% 파라미터 학습)** | **69.10%** | **58.84%** | 7.56%p | 1622s |
| v9 전체 fine-tune (100% 파라미터) | 69.07% | 58.78% | 7.56%p | 1777s |

**가설 기각.** 예상과 정반대로:
1. `classifier_only`(가장 강하게 얼림)는 fine-tuning을 안 한 것보다도 더 나빴음 — 표현력 부족.
2. `freeze_cnn`(96%)은 v9(100%)와 평균·표준편차 모두 거의 완전히 일치 — freeze 정도를 조절해도 분산에 변화 없음.
3. **결론**: 분산은 과적합 때문이 아니라, 피험자 본인의 신호 자체가 원래 쉽거나 어렵다는 **데이터 쪽 근본 차이**. 세 가지 다른 학습 전략에서도 같은 피험자(S01/S05/S40은 항상 잘됨, S28/S31은 항상 안 됨)가 반복됐다 (`results/v10/freeze_comparison.png`).

**종합 결론**:

2. 단일 피험자 baseline(82.7%) 자체가 이미 **일부 피험자에게는 풀링 모델만으로 달성 가능**하다는 것이 v9~v10에서 반복 확인됨 — 남은 격차는 "모델 전체의 한계"가 아니라 "특정 피험자 그룹에 풀링이 불리하게 작용하는 문제"로 더 정확히 좁혀짐.
3. 라벨-EMG 시차 보정은 이 데이터셋(restimulus 사용)에서는 가설이 틀렸다는 것이 명확히 확인된 막힌 길 — 향후 재시도 불필요.
4. Freeze 강도 조절도 분산 해결에는 막힌 길로 확인됨 — 다음 시도(Center Loss 등)는 "과적합 억제"가 아닌 다른 메커니즘으로 접근해야 함.
5. 클래스 불균형 보정(class weight, focal loss 등)은 **잘못 쓰면 정규화/아키텍처 개선보다 훨씬 크게 성능을 깎을 수 있음** — 적용 시 반드시 rest class recall과 전체 accuracy를 함께 모니터링하고, 체크포인트는 raw loss가 아니라 목표 지표(macro-F1 등)로 선택해야 함.

## 11. v11 — Center Loss로 클래스 경계 보강 시도 (안전했지만 무효과)

v10에서 "분산은 과적합 문제가 아니다"가 확인되어, 같이 제안됐던 두 번째 전략(Center Loss로 클래스 경계를 더 뚜렷하게)을 풀링 베이스 모델 단계에서 시도 (`code/models_v11.py`, `code/train_cnn_v11.py`). v8과 동일 데이터/아키텍처에 CrossEntropy(label_smoothing 0.1) + 0.01×CenterLoss를 더해 처음부터 재학습. v3~v5의 FocalLoss 사고와 무관한 메커니즘이라 매 epoch마다 rest recall을 모니터링하는 안전장치를 추가.

| Model | Test Acc | Test Macro-F1 | Rest Recall |
|---|---|---|---|
| v8 (CE only) | 68.69% | 56.92% | 정상 |
| v11 (CE + CenterLoss 0.01) | 68.64% | 57.04% | **91.47%** (학습 내내 90~98% 유지, 붕괴 없음) |

**안전성은 확인, 효과는 없음.** 차이(-0.05p/+0.12p)는 측정 잡음 수준. 가장 약했던 E2 그룹(클래스 18~40)만 따로 봐도 평균 F1 변화 +0.005, 나머지 그룹도 -0.0016으로 거의 그대로 — 의도했던 "비슷한 제스처 구분 개선"이 전혀 나타나지 않음. v10(가설이 틀림)과는 다른 종류의 결과로, "방향은 그럴듯하지만 이 lambda(0.01)에서는 측정되는 효과가 없었다"로 기록 (lambda를 더 키우면 다를 수 있으나 불안정 위험도 커짐, 우선순위 낮춤).

## 13. v12 — "어려운 피험자"의 정체 진단 (모델 학습 없는 분석 버전)

v9~v11에서 학습 전략(시차보정/freeze/center loss)이 전부 막힌 길로 끝난 뒤, 처음으로 모델을 전혀 학습하지 않고 **신호 자체를 진단**하는 분석을 진행 (`code/diagnose_subjects.py`). 피험자별 정규화 적용 전 원본 필터링 신호에서 직접 계산 가능한 세 지표를 40명 전체에 뽑아 v9의 피험자별 base_acc와 상관관계 분석:

| 지표 | base_acc와의 피어슨 상관계수 | p-value |
|---|---|---|
| **separability_score** (50클래스 간 MAV의 ANOVA F값) | **r=+0.749** | 2.8e-08 |
| **SNR(dB)** (움직임 RMS/rest RMS) | **r=+0.700** | 4.9e-07 |
| channel_cv (채널별 RMS 변동계수, 전극불량 가설) | r=+0.021 | 0.90 (관계 없음) |

**핵심 발견**: 가장 어려운 피험자(S28, S31, S04, S26, S07)는 전부 SNR<10dB·separability<175이고, 가장 쉬운 피험자(S05, S40, S01)는 전부 SNR>12dB·separability>350 (`results/v12/diagnostics.png`). 전극 불량 가설(channel_cv)은 완전히 기각됨. 즉 "어려운 피험자"는 측정 결함이 아니라 **근전도 신호 자체가 약하고(낮은 SNR) 동작 간 신호 패턴 차이가 본질적으로 작은(낮은 separability)** 사람들 — 전처리나 모델로 고치기 어려운 생체신호 자체의 한계에 가깝다는 것이 정량적으로 확인됨.

**추가 분석 — SNR과 separability의 상호 상관**: 둘이 독립적인지 확인하기 위해 편상관/다중회귀 진행. SNR과 separability 자체의 상관관계 r=+0.738(p=5.5e-08)로 서로 강하게 얽혀 있음. 편상관 결과 separability는 SNR을 통제해도 영향력이 크게 유지됨(0.749→0.482)인데 반해, SNR은 separability를 통제하면 크게 줄어듦(0.700→0.330) — **separability가 더 근본적인 변수이고, SNR의 영향력 상당 부분은 separability를 통한 간접 효과**로 해석됨. 다중회귀 결합 R²(0.608)도 separability 단독(0.561)보다 겨우 +4.7%p 추가라 두 지표가 사실상 비슷한 정보를 담고 있음. 함의: 신호를 더 깨끗하게(SNR 개선) 만드는 단일 방향에 집중하면 separability도 같이 개선될 가능성이 있음.

## 14. v13 — 웨이블릿 디노이징 시도 (상관관계 ≠ 인과관계로 기각)

v12의 "SNR을 개선하면 separability도 같이 좋아질 가능성" 제안을 직접 검증. `code/data_utils.wavelet_denoise()`(db4 웨이블릿, 4레벨 분해, soft-threshold)로 모든 피험자의 신호를 디노이징한 뒤, 모델 재학습 없이 v12와 동일한 방식으로 SNR/separability를 재계산해 비교 (`code/diagnose_denoise.py`).

| | SNR 변화 | Separability 변화 |
|---|---|---|
| 전체 40명 평균 | **+0.64dB** (개선) | **-1.99** (악화) |
| 어려운 5명(S28,S31,S04,S26,S07) | +0.77dB | -0.91 |
| 나머지 35명 | +0.62dB | -2.15 |

**가설 기각.** SNR은 기대대로 거의 모든 피험자에서 개선됐지만, separability는 거의 모든 피험자에서 악화됨 (`results/v13/denoise_effect.png`). v12에서 관찰한 SNR↔separability의 강한 상관관계(r=0.738)는 **사람들 사이의 자연스러운 차이를 반영한 상관관계였을 뿐, 한쪽을 인위적으로 조작하면 다른 쪽이 따라오는 인과관계는 아니었다.** 디노이징이 잡음으로 간주해 깎아낸 신호 성분 중 일부가 실제로는 클래스 구분에 쓰이던 유용한 정보였을 가능성이 높음. 진단 단계(GPU 없이 CPU로 수 분)에서 역효과가 명확히 드러나, 비용이 큰 모델 재학습으로는 진행하지 않음.

## 15. v14 — 클래스 그룹화 진단 (이 프로젝트 첫 부분적 긍정 신호)

| 클래스 수(k) | 전체 acc | 어려운 5명 | 나머지 35명 | 격차 |

**부분적으로 긍정적인 결과.** 클래스를 단순화할수록 격차가 꾸준히 줄고(k=10에서 35.8% 감소), 어려운 피험자가 절대 수치로도 더 많이 개선됨(+21.23p vs 나머지의 +16.65p). 다만 격차가 완전히 사라지지는 않음(k=10에서도 8.19p 남음) — 어려운 피험자 문제의 약 1/3은 "같은 계열 내 세부 구분 어려움"으로 설명되지만 나머지 2/3는 클래스 단순화로도 해소되지 않는 더 근본적인 어려움. k=10 클러스터는 E3(라벨 41~49)가 깨끗하게 독립 클러스터로 분리되는 등 운동 세트(Exercise) 구조와 의미 있게 맞아떨어짐. v9~v11, v13이 전부 무효/역효과였던 것과 달리, **이 프로젝트 최초로 부분적으로나마 명확한 긍정 신호**. 단, 이는 사후 그룹화 추정이라 실제로 k=10 분류기를 처음부터 학습시켜야 재현 여부를 확인할 수 있음 (다음 단계).

v14의 사후 그룹화 추정이 실제 학습에서도 재현되는지 검증. v14의 k=10 클러스터 할당으로 v8 데이터의 라벨을 재매핑해, 동일 아키텍처(SubjectAwareCNNLSTMAttention)/동일 레시피로 10클래스 분류기를 처음부터 새로 학습 (`code/train_cnn_v15.py`).

## 17. v16 — 2단계 계층적 분류기 (좋은 부분을 합쳤는데 전체는 더 나빠짐)

v15의 이득을 50클래스 전체 문제에 적용하기 위해, 1단계(v15 체크포인트 재사용, 10개 상위클래스 예측) → 2단계(클러스터별 서브 분류기 9개, 클러스터 내부 fine label 예측)로 이어지는 하드 라우팅 캐스케이드를 구성 (`code/train_stage2_v16.py`, `code/evaluate_v16.py`).

| | v8(단일 50클래스) | v16(2단계 계층) | 차이 |
|---|---|---|---|
| 전체 acc | 68.69% | 68.02% | -0.67p |
| 전체 macro-F1 | 56.92% | 56.41% | -0.51p |
| 어려운 5명 | 57.52% | **56.04%** | **-1.48p (더 나빠짐)** |
| 나머지 35명 | 70.29% | 69.72% | -0.57p |
| 격차 | 12.77p | **13.68p** | **+0.91p (더 벌어짐)** |

**가설은 맞았지만 조립 방식이 틀렸다.** 원인: (1) 1단계 라우팅 실수는 2단계가 복구할 수 없음(클러스터가 서로 겹치지 않아 잘못 보내지면 100% 오답) — 캐스케이드 분류기의 잘 알려진 구조적 약점. (2) 어려운 피험자는 1단계 정확도도 더 낮음(79.27% vs 86.99%, v15에서 확인). (3) 1단계가 맞아도 2단계 내부에서 어려운 피험자 정확도가 여전히 낮음(약 70.7% vs 80.2% 추정) — 최종 정확도가 두 단계 정확도의 곱에 가까워 오차가 누적·증폭됨. 클러스터 9(20클래스, rest 포함, 거대 흡수 클래스)의 서브 분류기 학습만 49분(전체 stage-2 학습시간의 70%)이 걸려 비용 측면의 불균등도 확인. v14/v15의 "클래스 단순화 효과"는 상위클래스 문제 자체에는 진짜였지만 하드 캐스케이드로 조립하는 과정에서 사라짐. 50클래스 메인 비교에서 v16은 v8보다 낮아 추천 모델로 채택하지 않음.

## 18. v17 — 소프트 라우팅 (방향은 맞지만 여전히 v8보다 낮음)

v16의 하드 라우팅 약점(1단계 실수를 2단계가 복구 불가)을 완화하기 위해, 재학습 없이 v15(1단계)/v16(2단계) 체크포인트를 재사용한 혼합 전문가(mixture of experts) 방식으로 추론만 변경 (`code/evaluate_v17.py`). 1단계의 클러스터별 확률을 그대로 살려 모든 클러스터의 2단계 전문가 의견을 가중 합산.

| | v16(하드 라우팅) | v17(소프트 라우팅) | v8(단일 50클래스) |
|---|---|---|---|
| 전체 acc | 68.02% | 68.19% | 68.69% |
| 전체 macro-F1 | 56.41% | 56.61% | 56.92% |
| 어려운 5명 | 56.04% | 56.33% | 57.52% |
| 나머지 35명 | 69.72% | 69.88% | 70.29% |
| 격차 | 13.68p | 13.55p | 12.77p |

**방향은 정확히 맞았지만 개선폭이 작음.** 소프트 라우팅이 모든 지표에서 하드 라우팅보다 일관되게 나아져 "복구 기회를 주면 도움된다"는 메커니즘 자체는 확인됐으나, 여전히 v8에는 못 미침. 원인: 클러스터 9(20클래스, rest 포함)의 테스트셋 평균 가중치가 0.62로 압도적 — 상대적으로 부정확한(val F1 0.556) 이 전문가의 의견이 모든 윈도우에 막대한 영향력을 행사해 소프트 믹싱 효과를 희석시킴. v14(가설 성공)→v16(조립 실패)→v17(조립 개선되지만 부족) 흐름에서 클러스터 크기 불균형이 매번 발목을 잡는 패턴이 뚜렷해짐. 50클래스 메인 비교에서 v17도 v8보다 낮아 추천 모델로 채택하지 않으나, 계층적 분류 계열 내에서는 v16보다 나은 현재 최선.

## 19. 향후 개선 후보 (v17 시점까지 미착수)

- 클러스터 9(거대 흡수 클래스) 재세분화 — 소프트 라우팅에서도 부작용의 핵심 원인으로 계속 지목됨, 다음 직접 후보
- 1단계+2단계 end-to-end 동시 학습 — 독립 학습 후 사후 결합 대신 손실 함수를 합쳐 한 번에 최적화
- 계층적 분류 계열은 일단 보류, 더 큰 레버리지가 있을 것으로 보이는 피험자별 fine-tuning/도메인 적응으로 우선 전환 검토
- v9(피험자별 fine-tuning) + v14(클래스 단순화) 결합 — 어려운 피험자에게만 단순화 태스크 적용
- 클러스터 수(k)를 더 세밀하게 스캔(5~35)해서 최적 지점 찾기
- 40명 개별 모델 학습 후 평균 정확도로 baseline(82.7%)과 진짜 동일 조건 비교
- 도메인 적응(DANN, MMD)
- 다른 디노이징 방법(adaptive Wiener filter, ICA 기반) — 우선순위 낮음
- Center Loss lambda 스윕, 약하게 튜닝한 Focal Loss 단독 시도 — 데이터 자체의 한계가 명확해진 만큼 기대치는 낮춰서 접근
- E2(취약 그룹) 전용 추가 특징/아키텍처 보강
