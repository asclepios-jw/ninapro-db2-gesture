## 0. 읽기 전에 — 이 코드가 하는 일

우리 코드는 한 문장으로 이렇다.

> **팔뚝 근전도 신호 조각을 받아서, 50가지 손동작 중 무엇인지 답하는 함수**를 만든다.

프로그래밍으로 치면 이런 함수를 만드는 셈이다.

```python
def 무슨동작인지_맞히기(근전도신호, 사람번호):
    ...
    return 50개_동작_각각의_점수
```

일반 함수와 다른 점은 **내부 계산에 쓰이는 숫자(가중치)를 사람이 안 정한다**는 것이다.
데이터를 보여주면서 컴퓨터가 스스로 그 숫자들을 맞춰간다. 이게 "학습"이다.

## 1. 먼저 알아야 할 3가지 개념

### 1-1. 텐서(tensor) = 숫자를 담은 다차원 상자

Python의 리스트를 여러 겹 겹친 것과 비슷하다.

```python
# 1차원: 그냥 숫자 나열
[1, 2, 3]

# 2차원: 표 (행 × 열)
[[1, 2, 3],
 [4, 5, 6]]

# 3차원: 표를 여러 장 쌓은 것
```

딥러닝에서는 이걸 **텐서**라고 부르고, 크기를 `(2, 3)` 처럼 괄호로 쓴다.
우리 코드에 계속 나오는 표기를 미리 익혀두자.

| 표기 | 뜻 |
|---|---|
| `B` | 배치(batch) 크기 — 한 번에 처리하는 데이터 개수 (우리는 256개) |
| `24` | 채널 수 — 센서 채널 24개 |
| `600` | 시간 길이 — 0.3초를 2000Hz로 재면 600개 숫자 |

그래서 `(B, 24, 600)`은 **"데이터 256개, 각각 24채널짜리 신호이고, 각 채널은 숫자 600개"** 라는 뜻이다.

### 1-2. 클래스(class) = 나만의 부품 만들기

Python에서 `class`는 "관련된 데이터와 함수를 하나로 묶은 틀"이다.
딥러닝에서는 **모델을 클래스로 만든다.** 기본 형태는 이렇다.

```python
class 내모델(nn.Module):          # nn.Module을 상속 = "딥러닝 부품"이라고 선언
    def __init__(self):          # ① 부품 준비 (한 번만 실행)
        super().__init__()
        self.층1 = ...            # 쓸 재료들을 미리 만들어 둠

    def forward(self, x):        # ② 실제 계산 (데이터 들어올 때마다 실행)
        return self.층1(x)
```

핵심은 두 함수뿐이다.

- **`__init__`** : 요리 전에 재료를 손질해 두는 것. 어떤 층을 쓸지 정의만 한다.
- **`forward`** : 실제 요리. 입력 `x`가 들어오면 층들을 순서대로 통과시킨다.

### 1-3. "층(layer)"이란

층은 **숫자 상자를 다른 모양·다른 값으로 바꿔주는 계산기**다. 우리가 쓰는 층들:

| 층 | 하는 일 (비유) |
|---|---|
| `Conv1d` | 신호를 훑으면서 **패턴을 찾는** 돋보기 |
| `BatchNorm1d` | 숫자 크기를 **적당한 범위로 조절** (학습이 안정됨) |
| `ELU` | 계산에 **구부러짐(비선형)** 을 넣어줌. 없으면 층을 쌓아도 의미가 없다 |
| `MaxPool1d` | 신호를 **절반으로 요약** (긴 걸 짧게) |
| `LSTM` | 시간 순서를 **기억하면서** 읽는 층 |
| `Linear` | 숫자들을 **섞어서 다른 개수로** 바꿈 |
| `Embedding` | 번호(예: 3번 사람)를 **의미 있는 숫자 묶음**으로 바꿈 |
| `Dropout` | 학습 중 일부를 **랜덤으로 끄기** (외우는 것 방지) |

## 3. 첫 번째 부품 — Attention (중요한 순간에 집중하기)

```python
class Attention(nn.Module):
    def __init__(self, hidden_dim):
        super().__init__()
        self.attention = nn.Sequential(
            nn.Linear(hidden_dim, hidden_dim),
            nn.Tanh(),
            nn.Linear(hidden_dim, 1, bias=False)
        )

    def forward(self, lstm_out):
        w = F.softmax(self.attention(lstm_out), dim=1)
        return torch.sum(w * lstm_out, dim=1), w
```

### 이게 왜 필요한가

0.3초 신호에는 150개 시점이 있다. 그런데 **모든 순간이 똑같이 중요하진 않다.**
주먹을 쥘 때 힘이 가장 들어가는 순간이 정보가 많고, 시작 부분은 애매하다.

Attention은 **"어느 순간이 얼마나 중요한지 점수를 매겨서, 중요한 쪽에 비중을 더 주고 하나로 합치는"** 부품이다.

### 코드 한 줄씩

**`nn.Sequential(...)`** — 층들을 순서대로 묶어주는 상자다. 안에 넣은 순서대로 통과한다.

```python
nn.Linear(hidden_dim, hidden_dim),   # 숫자 섞기 (256개 → 256개)
nn.Tanh(),                           # 구부러짐 추가
nn.Linear(hidden_dim, 1, bias=False) # 256개 → 1개 (= "이 순간의 중요도 점수")
```

이 세 층을 통과하면, 각 시점마다 **점수 1개**가 나온다.

**`F.softmax(..., dim=1)`** — 점수들을 **합이 1이 되는 비율**로 바꾼다.

```python
# 예: 점수가 [2.0, 1.0, 0.5] 였다면
# softmax 후: [0.63, 0.23, 0.14]   ← 합 = 1
```

이러면 "첫 번째 순간이 63% 중요하다"처럼 해석할 수 있다. `dim=1`은 "시간 축 방향으로 계산해라"는 뜻이다.

**`torch.sum(w * lstm_out, dim=1)`** — 가중 평균을 낸다.

```python
w * lstm_out          # 각 시점의 값에 중요도를 곱함
torch.sum(..., dim=1) # 시간 축으로 다 더함 → 시점 150개가 1개로 합쳐짐
```

즉 **중요한 시점의 정보를 더 많이 담은 요약 벡터 1개**가 나온다.

> `return A, B` 처럼 쉼표로 두 개를 반환하면, 받을 때 `x, y = 함수()` 로 받는다.
> 여기서는 (요약 결과, 중요도 점수) 두 개를 반환한다. 점수는 나중에 "모델이 어디를 봤나" 확인용이다.

## 4. 두 번째 부품 — 신호에서 직접 숫자 뽑아내기

```python
def compute_td_features(emg, thr=0.01, eps=1e-6):
    rms = torch.sqrt(torch.mean(emg * emg, dim=2) + eps)
    mav = torch.mean(emg.abs(), dim=2)
    d   = emg[:, :, 1:] - emg[:, :, :-1]
    wl  = d.abs().sum(dim=2)
    prod = emg[:, :, :-1] * emg[:, :, 1:]
    zc   = (((prod < 0) & (d.abs() > thr)).float()).sum(dim=2)
    d1  = emg[:, :, 1:-1] - emg[:, :, :-2]
    d2  = emg[:, :, 2:]   - emg[:, :, 1:-1]
    ssc = (((d1 * d2) < 0) & ((d1.abs() > thr) | (d2.abs() > thr))).float().sum(dim=2)
    return torch.cat([rms, mav, wl, zc, ssc], dim=1)
```

### 이게 왜 필요한가

딥러닝은 특징을 **스스로** 배운다. 그런데 근전도 연구자들이 수십 년간 써온 **검증된 계산식**들이 있다.
"이미 좋다고 알려진 것을 직접 계산해서 같이 넣어주면 도움이 되지 않을까?" 해서 추가한 부분이다.
(실제로 어려운 피험자에서 +0.93%p 개선이 있었다.)

이건 `class`가 아니라 **그냥 함수**다. 학습되는 숫자가 없고 순수 계산만 하기 때문이다.

### 슬라이싱 문법 먼저

Python 리스트에서 배운 슬라이싱을 텐서에도 쓴다. 대괄호 안에 콤마로 차원을 구분한다.

```python
emg[:, :, 1:]     # 모든 데이터, 모든 채널, 시간은 1번째부터 끝까지
emg[:, :, :-1]    # 모든 데이터, 모든 채널, 시간은 처음부터 마지막-1까지
```

이 둘을 빼면 **"바로 옆 값과의 차이"** 가 된다. 신호가 얼마나 급하게 변하는지 알 수 있다.

```python
d = emg[:, :, 1:] - emg[:, :, :-1]
# 신호가 [3, 5, 4] 였다면 → d = [5-3, 4-5] = [2, -1]
```

### 다섯 가지 특징 각각

**① RMS (제곱평균제곱근) — 신호의 세기**

```python
rms = torch.sqrt(torch.mean(emg * emg, dim=2) + eps)
```

제곱하고 → 평균 내고 → 루트. 근육이 얼마나 세게 수축했는지를 나타낸다.
`+ eps`(아주 작은 값 0.000001)를 더하는 이유는 **0의 제곱근에서 계산 오류가 나는 걸 막기 위한 안전장치**다.

`dim=2`는 "시간 축으로 계산"이라는 뜻이다. 그래서 결과는 `(B, 12)` — 데이터별로 채널 12개의 값이 남는다.

**② MAV (평균절대값) — 신호의 세기 (다른 방식)**

```python
mav = torch.mean(emg.abs(), dim=2)
```

절댓값의 평균. RMS와 비슷하지만 계산이 더 단순하다.

**③ WL (파형 길이) — 신호가 얼마나 요동쳤나**

```python
wl = d.abs().sum(dim=2)
```

옆 값과의 차이(`d`)를 다 절댓값으로 더한다. 신호가 복잡하게 떨렸으면 값이 커진다.

**④ ZC (영점 교차) — 신호가 0을 몇 번 넘나들었나**

```python
prod = emg[:, :, :-1] * emg[:, :, 1:]
zc = (((prod < 0) & (d.abs() > thr)).float()).sum(dim=2)
```

여기 트릭이 있다. **옆 값끼리 곱해서 음수면 부호가 바뀐 것**이다.

```python
3 * 5 = 15   (양수) → 부호 안 바뀜
3 * -2 = -6  (음수) → 0을 넘어갔다!
```

`& (d.abs() > thr)`는 **"변화가 너무 작으면 무시"** 라는 조건이다(`thr=0.01`).
잡음 때문에 0 근처에서 미세하게 떨리는 걸 세지 않으려는 안전장치다.
`&`는 "그리고"(둘 다 참), `.float()`는 True/False를 1/0 숫자로 바꾸는 것이다. 그래야 더할 수 있다.

**⑤ SSC (기울기 부호 변화) — 신호의 방향이 몇 번 바뀌었나**

```python
d1 = emg[:, :, 1:-1] - emg[:, :, :-2]   # 앞쪽 기울기
d2 = emg[:, :, 2:]   - emg[:, :, 1:-1]  # 뒤쪽 기울기
ssc = (((d1 * d2) < 0) & (...)).float().sum(dim=2)
```

기울기 두 개를 곱해서 음수면 **오르다가 내려갔거나(꼭대기), 내리다가 올라간 것(골짜기)** 이다.
`|`는 "또는"(하나라도 참)이라는 뜻이다.

### 마지막: 다 이어붙이기

```python
return torch.cat([rms, mav, wl, zc, ssc], dim=1)
```

`torch.cat`은 **여러 텐서를 이어붙이는(concatenate)** 함수다.
각각 `(B, 12)`짜리 5개를 옆으로 붙이면 `(B, 60)`이 된다. **채널 12개 × 특징 5개 = 60개 숫자**다.

## 5. 본체 — 모델 전체

이제 위 부품들을 조립한다.

### 5-1. `__init__` : 재료 준비

```python
class SubjectAwareCNNLSTMAttentionFeat(nn.Module):
    def __init__(self, n_channels=24, n_classes=50, n_subjects=40, emb_dim=32,
                 lstm_hidden=128, lstm_layers=2, n_emg=12, feat_hidden=64):
        super().__init__()
```

**함수 매개변수의 기본값**은 배웠을 것이다(`n_channels=24`). 값을 안 주면 24를 쓴다는 뜻이다.

| 매개변수 | 뜻 |
|---|---|
| `n_channels=24` | 입력 채널 24개 |
| `n_classes=50` | 맞혀야 할 동작 50가지 |
| `n_subjects=40` | 사람 40명 |
| `emb_dim=32` | 사람 정보를 32개 숫자로 표현 |
| `lstm_hidden=128` | LSTM 내부 크기 |
| `n_emg=12` | 앞쪽 12채널이 원본 근전도 신호 |

**`super().__init__()`** — 부모 클래스(`nn.Module`)의 준비 작업을 실행하는 것이다. 안 쓰면 PyTorch가 층을 인식하지 못한다. **딥러닝 클래스에서는 무조건 첫 줄에 쓴다**고 외우면 된다.

#### 사람 정보 저장소

```python
self.subject_emb = nn.Embedding(n_subjects + 1, emb_dim)
```

**`Embedding`은 번호 → 숫자 묶음 변환표**다. 사전(dictionary) 같은 걸 상상하면 된다.

```
1번 사람 → [0.2, -0.5, 0.8, ... ]  (32개 숫자)
2번 사람 → [-0.1, 0.3, 0.4, ... ]  (32개 숫자)
```

이 숫자들도 **학습으로 정해진다.** "이 사람의 신호는 이런 특성이 있다"를 컴퓨터가 알아서 정리하는 셈이다.
`+1`은 번호 여유분이다(0번을 쓰거나 예외를 위해).

> 이게 우리 프로젝트의 핵심 아이디어다. 사람마다 신호가 달라서 성능이 떨어지는 문제를,
> **개인차를 지우는 대신 "이 사람은 이런 사람"이라고 알려주는 방식**으로 풀었다.

#### CNN — 패턴 찾기

```python
self.cnn = nn.Sequential(
    nn.Conv1d(n_channels, 64, kernel_size=5, padding=2), nn.BatchNorm1d(64), nn.ELU(), nn.MaxPool1d(2),
    nn.Conv1d(64, 128, kernel_size=3, padding=1), nn.BatchNorm1d(128), nn.ELU(), nn.MaxPool1d(2),
)
```

같은 4종 세트가 두 번 반복된다: **Conv → BatchNorm → ELU → MaxPool**

**`Conv1d(24, 64, kernel_size=5, padding=2)`** 를 풀어보면:

- 입력 채널 24개를 받아 → 출력 채널 64개를 만든다
- `kernel_size=5` : 한 번에 **5개 시점씩 묶어서** 본다 (돋보기 크기)
- `padding=2` : 양쪽 끝에 2칸씩 0을 덧대서 **길이가 안 줄어들게** 한다

돋보기(커널)가 신호 위를 왼쪽부터 오른쪽까지 훑으면서 "이런 모양이 있나?"를 찾는다.
출력 채널 64개는 **64가지 다른 패턴을 동시에 찾는다**는 뜻이다.

**`MaxPool1d(2)`** — 2칸씩 묶어서 큰 값만 남긴다. 길이가 절반이 된다.

```python
[3, 7, 2, 5] → MaxPool(2) → [7, 5]
```

그래서 시간 길이가 이렇게 줄어든다: **600 → 300 → 150**

#### LSTM — 시간 흐름 읽기

```python
self.lstm = nn.LSTM(128 + emb_dim, lstm_hidden, num_layers=lstm_layers,
                    batch_first=True, bidirectional=True)
```

- `128 + emb_dim` = `128 + 32` = **160** ← CNN 결과(128) + 사람 정보(32)를 합쳐서 넣는다
- `num_layers=2` : LSTM을 2층 쌓는다
- `batch_first=True` : 데이터 모양을 `(B, 시간, 특징)` 순서로 쓴다는 약속
- `bidirectional=True` : **앞→뒤 방향과 뒤→앞 방향을 모두 읽는다**

양방향이라 출력 크기가 2배가 된다. `128 × 2 = 256`.

#### Attention

```python
self.attention = Attention(lstm_hidden * 2)
```

3장에서 만든 부품을 가져다 쓴다. `128 * 2 = 256` 크기를 처리하도록 설정.

#### 특징 처리 MLP

```python
n_feat = 5 * n_emg      # 5 × 12 = 60
self.feat_mlp = nn.Sequential(
    nn.BatchNorm1d(n_feat),
    nn.Linear(n_feat, feat_hidden), nn.BatchNorm1d(feat_hidden), nn.ELU(),
    nn.Linear(feat_hidden, feat_hidden), nn.ELU(),
)
```

4장에서 계산한 60개 숫자를 처리하는 부분이다. `Linear`로 60 → 64 → 64로 바꾼다.

**여기서 첫 줄 `BatchNorm1d(n_feat)`가 중요하다.** 왜냐하면:

- RMS는 대략 0~1 정도의 값
- WL(파형 길이)은 수백까지 갈 수 있는 값

**크기 차이가 너무 크면 큰 값이 학습을 지배해버린다.** BatchNorm으로 다 비슷한 범위로 맞춰준다.

#### 마지막 판정층

```python
self.fc = nn.Sequential(
    nn.Dropout(0.4), nn.Linear(lstm_hidden * 2 + feat_hidden, n_classes)
)
```

- `Dropout(0.4)` : 학습 중 40%를 랜덤으로 끈다. **답을 외우는 걸 방지**하는 장치다.
- `Linear(256 + 64, 50)` = `Linear(320, 50)` : 두 갈래를 합친 320개 숫자를 **50개 동작 점수**로 변환.

---

### 5-2. `forward` : 실제 계산

```python
def forward(self, x, subject_idx):
    feats = compute_td_features(x[:, :self.n_emg, :])   # ①

    s_emb = self.subject_emb(subject_idx)               # ②
    h = self.cnn(x)                                     # ③
    h = h.transpose(1, 2)                               # ④
    T_prime = h.shape[1]
    s_emb_exp = s_emb.unsqueeze(1).expand(-1, T_prime, -1)  # ⑤
    h = torch.cat([h, s_emb_exp], dim=-1)               # ⑥
    out, _ = self.lstm(h)                               # ⑦
    context, _ = self.attention(out)                    # ⑧

    f = self.feat_mlp(feats)                            # ⑨
    return self.fc(torch.cat([context, f], dim=1))      # ⑩
```

한 단계씩 따라가 보자. 입력은 `x = (256, 24, 600)`, `subject_idx = (256,)`이다.

**① 수공 특징 계산**

```python
feats = compute_td_features(x[:, :self.n_emg, :])
```

`x[:, :12, :]`는 **앞쪽 12채널만** 가져오는 것이다. (24채널 중 앞 12개가 원본 신호, 뒤 12개는 포락선)
결과: `(256, 60)`

**② 사람 정보 꺼내기**

```python
s_emb = self.subject_emb(subject_idx)
```

사람 번호 → 32개 숫자. 결과: `(256, 32)`

**③ CNN 통과**

```python
h = self.cnn(x)
```

`(256, 24, 600)` → `(256, 128, 150)`
채널이 24→128로 늘고(패턴 128가지), 시간이 600→150으로 줄었다.

**④ 축 순서 바꾸기**

```python
h = h.transpose(1, 2)
```

`transpose(1, 2)`는 **1번 축과 2번 축의 자리를 바꾸는** 것이다.

```
(256, 128, 150) → (256, 150, 128)
      채널 시간         시간 채널
```

왜 바꾸나? CNN은 `(배치, 채널, 시간)` 순서를 쓰는데 **LSTM은 `(배치, 시간, 특징)` 순서**를 원하기 때문이다.
부품마다 요구하는 모양이 달라서 맞춰주는 작업이다.

**⑤ 사람 정보를 시간만큼 복사**

```python
T_prime = h.shape[1]                                   # 150
s_emb_exp = s_emb.unsqueeze(1).expand(-1, T_prime, -1)
```

문제가 있다. 신호는 시점이 150개인데 사람 정보는 딱 1개다. 붙이려면 개수를 맞춰야 한다.

- `unsqueeze(1)` : 1번 자리에 **빈 축을 끼워넣기**. `(256, 32)` → `(256, 1, 32)`
- `expand(-1, 150, -1)` : 그 축을 **150번 복사**. `(256, 1, 32)` → `(256, 150, 32)`
- `-1`은 "이 축은 그대로 둬라"는 뜻

즉 **"이 사람은 3번 사람"이라는 정보를 150개 시점 전부에 붙여주는** 것이다.

**⑥ 신호 + 사람 정보 합치기**

```python
h = torch.cat([h, s_emb_exp], dim=-1)
```

`(256, 150, 128)`과 `(256, 150, 32)`를 마지막 축으로 붙여서 → `(256, 150, 160)`
`dim=-1`은 "맨 마지막 축"이라는 뜻이다.

**⑦ LSTM 통과**

```python
out, _ = self.lstm(h)
```

`(256, 150, 160)` → `(256, 150, 256)` (양방향이라 128×2)

> `_`(밑줄)은 **"반환값을 받긴 하지만 안 쓸 거야"** 라는 관례다.
> LSTM은 (결과, 내부기억상태) 두 개를 주는데 우리는 결과만 필요하다.

**⑧ Attention으로 요약**

```python
context, _ = self.attention(out)
```

150개 시점을 중요도에 따라 하나로 합친다. `(256, 150, 256)` → `(256, 256)`

**⑨ 수공 특징 처리**

```python
f = self.feat_mlp(feats)
```

`(256, 60)` → `(256, 64)`

**⑩ 두 갈래 합쳐서 최종 답**

```python
return self.fc(torch.cat([context, f], dim=1))
```

- 딥러닝이 배운 정보(256개) + 사람이 계산한 특징(64개) = 320개
- `fc`를 통과 → `(256, 50)` — **데이터 256개 각각에 대해 50개 동작의 점수**

가장 점수가 높은 동작이 모델의 답이다.

## 6. 전체 흐름 한 장으로

```
입력: 신호 (256, 24, 600)  +  사람번호 (256,)
  │
  ├──────────────────────────┐
  │ [딥러닝이 배우는 길]        │ [사람이 계산해주는 길]
  ▼                          ▼
CNN                     compute_td_features
(256,128,150)              (256, 60)
  │                          │
transpose                  feat_mlp
(256,150,128)              (256, 64)
  │                          │
+ 사람정보(32) 결합            │
(256,150,160)                │
  │                          │
LSTM (양방향)                 │
(256,150,256)                │
  │                          │
Attention (시간 요약)          │
(256, 256)                   │
  │                          │
  └────────► 합치기 ◄─────────┘
            (256, 320)
                │
          Dropout + Linear
                ▼
          (256, 50) ← 50개 동작 점수
```

## 7. 처음 봤을 때 헷갈렸던 것들 (정리)

| 코드 | 뜻 |
|---|---|
| `super().__init__()` | 부모 클래스 준비 실행. 딥러닝 클래스 첫 줄에 필수 |
| `nn.Sequential(...)` | 층들을 순서대로 묶는 상자 |
| `dim=1`, `dim=2`, `dim=-1` | **몇 번째 축을 기준으로** 계산할지. `-1`은 맨 마지막 축 |
| `x[:, :12, :]` | 모든 데이터 / 앞 12채널만 / 모든 시간 |
| `emg[:, :, 1:] - emg[:, :, :-1]` | 옆 값과의 차이 (신호 변화량) |
| `torch.cat([a, b], dim=1)` | 두 텐서를 옆으로 이어붙이기 |
| `transpose(1, 2)` | 1번 축과 2번 축 자리 바꾸기 |
| `unsqueeze(1)` | 1번 자리에 빈 축 끼워넣기 |
| `expand(-1, 150, -1)` | 축을 150번 복사 (`-1`은 그대로) |
| `out, _ = ...` | 두 개 반환값 중 앞만 쓰고 뒤는 버림 |
| `.float()` | True/False → 1/0 숫자로 변환 (더하려면 필요) |
| `+ eps` | 0으로 나누기/루트 오류 방지용 아주 작은 값 |

## 8. 이 코드에서 기억할 설계 아이디어 3가지

**① 사람마다 다른 신호를 "사람 정보"로 알려준다 (`Embedding`)**
40명의 신호가 다 달라서 성능이 떨어지는 문제를, 개인차를 지우는 대신 **"이 사람은 이런 특성"이라고 모델에 알려주는** 방식으로 풀었다.

**② 딥러닝과 사람의 지식을 둘 다 쓴다 (두 갈래 구조)**
CNN이 스스로 배운 특징 + 근전도 연구에서 검증된 계산식(RMS, MAV 등)을 **합쳐서** 판단한다. 서로 놓치는 걸 보완한다.

**③ 모든 순간이 똑같이 중요하지 않다 (`Attention`)**
150개 시점을 그냥 평균 내지 않고, **중요한 순간에 비중을 더 주고** 요약한다.

## 마치며

처음 이 코드를 봤을 때는 `dim=`이랑 `transpose`만 봐도 머리가 아팠다.
그런데 알고 보니 대부분은 **"숫자 상자의 모양을 다음 부품이 원하는 형태로 맞춰주는 작업"** 이었다.

핵심 로직 자체는 생각보다 단순하다.

> 신호에서 패턴을 찾고(CNN) → 시간 흐름을 읽고(LSTM) → 중요한 순간을 강조하고(Attention)
> → 사람 정보와 검증된 특징을 합쳐서 → 50개 중 하나를 고른다.

문법이 어려워 보여도 겁먹지 말고, **텐서 모양이 어떻게 바뀌는지만 따라가면** 대부분 읽힌다.
